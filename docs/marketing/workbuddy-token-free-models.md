## 引子：积分不够用，先别急着掏钱

WorkBuddy 烧的是**积分**，不是 token。个人免费版每月 500 积分，与 CodeBuddy 同账号共享（实际额度以你账号内显示的为准）。

在动钱包之前，有四招零成本省积分的用法：

| 做法 | 为什么省 |
|---|---|
| 简单活走**快速模式** | 快速 / 均衡 / 极致三档，响应越快消耗越低。格式转换、文案润色没必要上极致 |
| 上下文窗口**保持默认 200K** | 每轮对话都会把当前上下文完整发给模型，窗口越大单轮越贵。开到 1M 不会让模型变聪明，只会让每轮成倍花钱 |
| **Max 模式保持关闭** | 关闭时系统会自动压缩上下文，减少长对话里的重复传输 |
| 长任务**开新会话** | 一个滚了几百轮的会话，每轮都在为前面的历史付费 |

真不够用了，两条路：**A 买官方套餐**（腾讯云 Token Plan / Coding Plan，省心但要花钱）；**B 接自定义模型**（WorkBuddy 支持任意 **OpenAI 兼容协议**的第三方模型，请求直接发往你填的接口，**不消耗 WorkBuddy 积分**）。

> 官方文档原话：自定义模型产生的全部费用（Token、订阅等）由您向第三方支付。
> 配置（含 API Key）只保存在本地 `workbuddy/models.json`，不上传云端。

这篇讲路线 B。

而路线 B 的第一步，几乎所有人都会想到同一件事：**既然要花钱，那能不能白嫖？**

## 一、想白嫖，先撞上三堵墙

白嫖的思路简单得很：找一家免费的大模型服务，把接口地址和 Key 填进 WorkBuddy，收工。

难的不是「填」，是「找」。找免费模型这件事，看起来最简单，实际上最容易翻车 —— 你会依次撞上三堵墙。

### 墙 1：哪个才是真免费？

「免费」这个词已经被用烂了。搜索引擎里能翻出一堆《免费大模型合集》，逐条点进去，你会发现所谓「免费」至少分五种：

| 名单上的说法 | 真相 |
|---|---|
| 新用户免费 / 首月 0 元 | **本质还是要付钱**，只是把账单推迟一个月 |
| 限时免费 | 现在真免费，但**随时可能收回** |
| 开源 / 开放权重 | 模型能免费下载 ≠ 有**免费的官方 API**。权重和接口是两件事 |
| 未确认 | 官网没写清楚，谁也不知道 |
| 官方长期免费 | ✅ 这才是你要的 |

问题在于：**这些区别，名单本身不会告诉你。** 一份静态名单只能抄下官网的宣传语，抄不下官网没写的部分。

### 墙 2：免费的速度到底怎么样？

「免费的一定慢」——这既是偏见，也可能是事实。但无论哪种，**你手上都没有数据**：

- 官网只会说「高性能」「极速」「毫秒级响应」，不会给你一个可比较的数字；
- 就算有第三方测过，测的也未必是你这条线路 —— 同一个入口，大陆直连和海外节点能差 **9 倍**（后面有实测）；
- 而且速度是个会变的量。今天 200ms，不代表下个月还是。

问题在于：**你要的是数字，不是形容词。**

### 墙 3：名单是死的，模型是活的

过去 10 天，这条流水线记下了 98 条变更：

| 类型 | 条数 |
|---|---:|
| 新增 New | 26 |
| 下线 Offline | 42 |
| 恢复 Recovered | 9 |
| 新增线路 New route | 20 |

**42 条下线 ≈ 每两天就有 4 个模型从「能用」变成「不能用」。**

你收藏的那篇文章，写的时候是真的。三个月后点进去：活动结束了、额度没了、接口改了、或者那家公司整个转型了。你按它配了半天，最后卡在 401。

问题在于：**名单是快照，你需要的是实况。**

> 所以真正稀缺的从来不是「免费模型的名单」——**名单遍地都是。稀缺的是有人每天替你把名单筛过一遍。**

## 二、有个网站，每天爬一遍、测一遍

FreeLLM（https://freellm.top/）每天跑三步：**抓取 → 实测 → 精选**。

这三步不是随便排的 —— 它正好一堵一堵地拆掉上面那三面墙：

| 步骤 | 拆掉哪堵墙 |
|---|---|
| **1 每天抓** | 墙 3：名单是死的 → 每天重新拉一遍，记下变更 |
| **2 每天测** | 墙 2：不知道速度 → 每个接口真发请求，给数字 |
| **3 精选** | 墙 1：不知道哪个真免费 → 速度和额度双达标才留下 |

前两步是手段，第三步是产出。

### 2.1 每天抓 —— 拆墙 3

每天从服务商的**官方模型接口**拉取当前可用模型，生成当日快照，再与前一天做差异比对，产出四类变更事件：

| 事件 | 含义 |
|---|---|
| **新增 New** | 新上线的模型，或新出现的调用线路 |
| **恢复 Recovered** | 之前掉线的模型重新可用 |
| **下线 Offline** | 确认已经不可用了 |
| **来源异常 Source issues** | 扫描本身失败了 —— 注意，这**不等于**项目下线 |

上面那张「98 条变更」的图，就是这条流水线过去 10 天的产出。

这些变更全部落在公开的**每日更新页**上：https://freellm.top/logs/ —— 每天打开一次，就知道今天有哪些模型上线下线。

### 2.2 每天测 —— 拆墙 2

光抓列表不够，**列表里有不等于接口活着**。所以每条资源都会被真实探测一遍：

- **探测方式**：直接请求服务商的官方 API 端点，**探测本身不带任何 Key**，所以结果很干净：
  `200` → 不注册就能用；`401/403` → 接口是活的、需要 Key；`404` → 路径可能变了；`429` → 被限流。
- **测延迟**：**预热 1 次**（先排除 DNS/TLS 建连开销），再取 **3 次成功请求往返延迟的中位数**。所以页面上的 `ms` 是**调用延迟**，不是一次建连的毛刺。
- **双视角**：一个是**大陆网络直连**（更接近你自己电脑的体验），另一个是**海外节点**（美 / 德 / 新 / 日 / 英）。两个视角分开记录，因为「快不快」取决于你在哪。

墙 2 要的「数字」，就是这一步给的。

### 2.3 精选 —— 拆墙 1：45 条里只留 8 条

这才是真正在做的事。页面上那个 **「◆ 加精」** 标签（本文叫它「精选」）不是编辑凭印象点的，判定只用两条**已经实测、已经核验**的证据，**两个条件同时满足**才入选：

**条件一：接口实测快**（大陆直连、预热 1 次后 3 次往返延迟的中位数）

| 档位 | 门槛 |
|---|---|
| `very_fast` | **≤ 200 ms** |
| `fast` | **≤ 400 ms** |
| 其它 | **不参评** |

**条件二：免费额度高**（要能读出数量级）

| 单位 | 门槛 |
|---|---|
| tokens | ≥ 1,000,000 |
| 次请求 | ≥ 100,000 |
| 积分 | ≥ 50,000 |

注意「额度」这一条，正是用来回答墙 1 的。它把前面那张「五种免费」的表变成了可计算的规则：**首月优惠价（本质还是要付钱）、未确认、开放权重，三类直接不参评。**

**关键的一条：没有实测值的条目一律不参评。** 不会拿「官网宣称延迟」或者「感觉挺快」来代替。

**筛选结果：45 条已核验的免费资源，只有 8 条通过。**

> 这个数字不是我算的——你去 https://freellm.top/ 看筛选条，**「◆ 加精」后面写的就是 08**，而「全部」是 45。

另外两个细节能看出这是个真操作，不是营销标签：

- **每条精选都把入选理由写在页面上**，鼠标悬停标签就能看到，比如「加精｜实测 222ms · 官方长期免费」。理由够不够，你自己判断。
- **入选日期只记首次**。脚本重跑不会把日期改新——标签的生效日期是历史事实，不能因为重跑就漂移。

### 2.4 精选不是一次性的

**案例：一个 243ms 的接口，也曾经掉线三天。**

本文下面要推荐的 **小红书 Dots · Dots3-Note Preview**，接口实测 **243 ms**，是精选条目之一。

但翻每日更新页会发现：

- **2026-09-12**，这条记录被标记为 **下线 Offline**；
- **2026-09-15**，又被标记为 **恢复 Recovered**。

**精选 ≠ 一劳永逸。** 今天入选，不代表下个月还在。如果这是一份静态名单，你在 9 月 12 日读到它，会照着配半天，然后怀疑自己哪里写错了。而在索引里，你一眼就能看到「它 12 号掉过线、15 号才回来」——**这是别人替你踩过的坑。**

### 2.5 精选也明确告诉你它没测什么

这一点比前面几条都重要。延迟数据的说明写得很直白：

> 只测量 API 网关的往返延迟，**不代表模型生成速度、免费额度或注册门槛**。

也就是说：243ms 是**接口响应快**，不代表模型吐字快、不代表额度大、不代表注册简单。这三件事它分开标注，不混为一谈。

同样，每条记录都带 **`lastVerifiedAt`（最后核验日期）**，并有一条硬门禁：**任何条目的核验日期超过 7 天，站点的健康检查就会直接失败**（构建流程报错退出）。所以你看到「核验于 2026-09-17」，就意味着它真的在 9 月 17 日被重新核对过，而不是「大概差不多」。

```bash
curl https://token.sensenova.cn/v1/models -H "Authorization: Bearer ${SENSENOVA_API_KEY}"
```

公测期 `pricing` 字段全是 0，可以直接据此判断哪些模型当前免费。

**WorkBuddy 配置（这里和别家不一样，注意）：**

```
接口地址:  https://token.sensenova.cn/v1/chat/completions   ← 必须填完整，不能只填到 /v1
API Key:   sk-xxx
模型名称:  sensenova-6.8-flash-lite
```

推荐先配 `sensenova-6.8-flash-lite`：它**支持工具调用**（WorkBuddy 读写文件靠这个），而且能识图，适合当办公主力。

> **核实状态说明**（这条和其他两条不同，说清楚）：`sensenova-6.8-flash-lite`、`sensenova-u1-fast` 来自官方 Token Plan 页面（2026-09-19 复核）；`sensenova-u1.5-lite` 来自商汤官方新闻稿；`deepseek-v4-flash` 与 `glm-5.2` 来自官方文档口径的整理，**接入前请用上面的 `/v1/models` 自查一次**。另外官方页面对免费额度有一句「特殊模型除外」，具体哪些除外以控制台为准。

### ④ Agnes AI —— 它有国内地址，别去连全球入口

Agnes AI 提供 OpenAI 兼容的多模态 API（文本 / 图像 / 视频），Free/default 层按模型限速，不用充值。

**它有两条接入地址，这是重点：**

| 入口 | 接口地址（完整路径） |
|---|---|
| 国际 | `https://apihub.agnes-ai.com/v1/chat/completions` |
| **国内** | **`https://api.agnes-ai.cn/v1/chat/completions`** |

两条地址都由官方文档给出：国际站在 `agnes-ai.com/en/docs/overview`，国内站在 `agnes-ai.cn/en/docs/overview`。**人在国内就该用后者。**

**为什么这个区分重要——看实测数据：**

| 探测视角 | 目标 | 延迟 |
|---|---|---|
| 大陆网络直连 | `apihub.agnes-ai.com`（全球入口） | **1828 ms** |
| 海外节点 | 同一个入口 | **221 ms** |

**同一个入口，国内直连比海外慢 8 倍。**

这也解释了为什么 Agnes AI **没有通过精选门槛**：精选要求大陆直连 ≤400ms，而它的接口探测是 **1050 ms**。**它被筛掉不是因为不好，是因为索引测的是它的全球入口。**

那换成国内地址是不是就快了？——**索引目前还没有实测过 `api.agnes-ai.cn` 这条地址，所以我不能替你打包票。** 这恰好是个诚实的边界：「官方给了国内地址」和「实测过它很快」是两件事，我不会把前者说成后者。

**模型清单**（爬虫观测，2026-09-17）：

| 模型 | 上下文 | 模态 | 限速 |
|---|---|---|---|
| `agnes-2.0-flash` | 256K | 文本 + 视觉 + 图像 + 推理 | 30 RPM |
| `agnes-1.5-flash` | 256K | 文本 + 视觉 | 30 RPM |
| `agnes-image-2.0-flash` | 4K | 图像 | 30 RPM (1K) |
| `agnes-image-2.1-flash` | 4K | 图像 | 30 RPM (1K) |
| `agnes-video-v2.0` | 4K | 视频 | 2 RPM |

官方目录另外给了一套 Free/default 口径：文本 20 RPM、图像按分辨率 20/10/1/1 RPM、视频 1 RPM。**两套数字不一致，以官方目录和你控制台里显示的为准。**

**接 WorkBuddy**：用 `agnes-2.0-flash`（256K 上下文，支持推理和视觉），接口地址填**国内那条**：

```
接口地址:  https://api.agnes-ai.cn/v1/chat/completions
模型名称:  agnes-2.0-flash
```

**注册入口**：国内 https://platform.agnes-ai.cn ｜ 国际 https://agnes-ai.com/

> 同样的坑再提醒一次：`agnes-image-*` 和 `agnes-video-*` 不是对话模型，**配不进 WorkBuddy 的自定义模型**，别在上面浪费时间。

## 五、配置到 WorkBuddy：三步，加一个必勾的开关

WorkBuddy 官方文档明确：自定义模型**可通过可视化界面配置，支持添加、编辑和删除，无需手动编辑配置文件**。所以优先用界面法。

### 第 1 步：打开入口

对话界面底部的**模型选择器** → 列表最底部的**「配置自定义模型」**；
或者：**设置 → 模型 → 添加模型**。

弹出的对话框顶部会写着「仅支持 OpenAI 兼容协议 API」—— 上面四家都符合。

### 第 2 步：选「自定义 / Custom」，填三个字段

提供商下拉里有预设项（智谱、Kimi、MiniMax、DeepSeek、Ollama 本地等，选预设会自动填好地址），**这几家都不在预设里，所以要选「自定义 / Custom」**，手动填：

```
提供商:    自定义 / Custom
接口地址:  https://discovery.intern-ai.org.cn/v1/chat/completions   ← 完整路径，以 /chat/completions 结尾
API Key:   sk-xxx
模型名称:  Atria-Dawn-Preview                                        ← 大小写敏感
```

**三个最常见的翻车点：**

1. **接口地址只填到域名**。必须填到 `/chat/completions`，中间不要出现多余斜杠。
2. **API Key 末尾粘进空格**。复制完回头看一眼。
3. **模型名称和服务商文档不一致**。这个字段是直接传给 API 的 `model` 参数，**大小写敏感**。

### 第 3 步：高级配置 —— 「工具调用」必须勾

**选「自定义 / Custom」时，能力标记一个都不会自动写入**（选标准供应商才会自动填）。这是最关键的一步：

| 开关 | 怎么填 |
|---|---|
| **工具调用** | **必勾。** WorkBuddy 靠 Function Calling 读写你的本地文件，不勾就只会跟你聊天、不会真动手 |
| 图片输入 | 只有模型真支持多模态才勾。**Atria 只吃文本，勾了会直接报错** |
| 推理模式 / 思考强度 | Atria 支持思考模式，可以勾；下面的强度档位按模型支持的范围选 |
| 自定义协议 | 只有接口地址**不是** `/chat/completions` 结尾时才开。这几家都不用开 |
| 上下文窗口 | 按模型实际能力填（Atria 是 256K）。不确定就留空用默认 |

**原则：拿不准就先只勾「工具调用」，跑通之后再逐项加。勾了模型不支持的能力，会直接导致请求失败。**

保存后，模型会出现在对话界面的模型选择器里，和内置模型并列。

## 六、配完先别丢一堆活进去

先让它做一件小事，比如：

> 把这个文件夹里的 csv 各读前 5 行，汇总成一张表

这一个动作同时验证三件事：**接口通不通、工具调用有没有真的生效、扣费正不正常**。

如果它能读文件、能汇总，说明「工具调用」生效了；如果它只是用文字跟你描述「你可以这样整理」，那就是开关没勾上。

## 七、配不通？按这个顺序查

| 现象 | 先查这个 |
|---|---|
| 保存后调用失败 | 接口地址是否完整、以 `/chat/completions` 结尾、无多余斜杠 |
| 401 / 鉴权失败 | API Key 是否复制完整、末尾是否有空格 |
| 404 / 模型不存在 | 模型名称是否与服务商文档完全一致（大小写敏感） |
| 能聊天但不动文件 | 「工具调用」没勾 —— 九成是这个 |
| 勾了图片输入就报错 | 取消掉，模型不支持 |
| 地址不是标准路径 | 开「自定义协议」开关，跳过路径校验与自动补全 |
