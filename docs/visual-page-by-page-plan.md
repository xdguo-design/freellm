# FreeLLM 全站视觉重构阶段计划

更新时间：2026-09-23

## 目标

本轮只做 **一套视觉：Aurora / 极光**。

原则：

- 不同时推进第二套主题。
- 不一次性改全站。
- 按页面逐个完成：设计收敛 → 开发 → 页面级视觉回归 → 修正 → 验收后再进入下一页。
- 每个页面只复用已经验收过的全局组件和设计 Token，不边做边改整站结构。
- 功能、SEO、数据逻辑保持不变，视觉重构不顺带做大规模业务重写。

## Aurora 视觉基线

- 页面：明亮、轻盈、玻璃感、极光渐变。
- 导航：深海军蓝侧栏，当前项蓝色高亮。
- 主色：蓝 / 青蓝，少量紫粉和薄荷绿作为层次色。
- 卡片：统一圆角、边框、阴影、内边距与等高规则。
- Hero：大标题 + 清晰说明 + 核心动作，背景使用柔和极光/抽象 AI 视觉。
- 字体层级：中文标题强、正文清晰，英文只做辅助信息，不抢主层级。
- 移动端：不做桌面版缩小；导航、Hero、筛选、卡片单独重排。

## 开发阶段

### Phase 0：冻结设计系统

先只定义 Aurora 的全局 Token 与基础组件：

- color / surface / border / shadow
- typography
- radius / spacing
- button / chip / input / tab
- card / section / hero
- sidebar / mobile navigation

验收条件：基础组件不再在后续页面中反复改规格。

### Phase 1：首页

范围：

- 顶部导航 / 侧栏
- Hero
- 今日 / 最新
- 分类与筛选
- 热门资源
- 资源卡片
- 学生优惠
- 对比 / 下载 / FAQ

重点：

- 今日 / 最新必须位于首页第一主内容层级。
- 资源卡同一行等高，底部操作对齐。
- 筛选紧凑，不形成第二个大 Hero。
- 移动端 Hero、搜索、导航不溢出。

验收：Desktop 1440 / Tablet 1024 / Mobile 390 三档截图通过。

### Phase 2：模型页

范围：

- 模型页 Hero
- 指标卡
- 模型筛选
- Provider / Model 卡片
- 对比区
- 模型详情入口

重点：模型信息密度高但不乱，卡片等高，长模型名/参数不撑破布局。

### Phase 3：Skills 页

范围：

- Skills Hero
- 搜索 / 状态 / 分类
- Skill 卡片
- 详情弹窗

重点：卡片层级统一；弹窗在窄屏完整可见；测试状态醒目但不过度强调。

### Phase 4：Tools 页

范围：

- Tools Hero
- 搜索 / 分类
- 工具卡片
- 工具详情页基础壳

重点：高密度工具目录可快速扫描，移动端分类横向可滑。

### Phase 5：Workflows 页

范围：

- Workflow Hero
- 工作流卡
- 节点链
- 组件库
- 配方详情

重点：方法链/步骤结构优先于装饰，流程节点清晰。

### Phase 6：更新页

范围：

- 更新 Hero
- 今日变化
- 时间线
- 统计 / 来源可信度 / 快速导航

重点：时间信息与状态信息一眼可读。

### Phase 7：关于页

范围：

- About Hero
- 价值主张
- 方法 / 标准 / 核验流程
- 社区 / 联系 / 里程碑

重点：阅读节奏优先，减少“每段一个卡片”的碎片感。

### Phase 8：全站统一回归

只在所有页面分别通过后做：

- 全站间距与字体统一
- 卡片高度与按钮位置一致性
- Desktop / Tablet / Mobile 横向溢出
- 键盘焦点与基础可访问性
- 首页到子页导航一致性
- 视觉截图归档

## 页面完成定义

每一页完成必须同时满足：

1. 页面视觉与 Aurora 基线一致。
2. 页面核心功能没有回归。
3. 同行卡片等高或明确采用内容自适应规则。
4. 390px 不出现页面级横向滚动。
5. 页面截图经过人工检查。
6. 自动化页面契约测试通过。

## 当前执行顺序

**现在只进入 Phase 0 + Phase 1：首页。**

首页验收完成之前，不开始模型页；模型页完成之前，不开始 Skills 页，以此类推。

第二套主题（Nebula / 星云）暂时冻结，等 Aurora 全站完成后再单独立项。
