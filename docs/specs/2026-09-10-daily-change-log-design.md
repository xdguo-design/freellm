# 每日新增与下线日志设计

## 目标

为 FreeLLM 增加公开 `/logs/` 页面。每天记录模型目录和 FreeLLM 资源的新增、下线、恢复及扫描状态；新增项目使用详细卡片，方便用户判断“是什么、从哪里来、如何使用、有什么限制”。

## 判定规则

- 模型使用 `id` 作为稳定键；资源使用 `id` 作为稳定键。
- 首次出现的模型或资源记录为 `new`。
- 同一模型在新提供商或新目录渠道出现时，记录为 `new_route`，不伪装成全新模型。
- 之前存在、当前成功快照中消失，或资源状态进入 `offline`、`expired`、`retired` 的记录为 `offline`。
- 之前下线、当前重新出现的记录为 `recovered`。
- 来源抓取失败只记录为 `source_unavailable`，绝不推断为下线。
- 第一次运行只建立基线，不把全量现有数据伪装成当天新增。

## 日志数据

每个北京时间日期写入 `data/daily-log/YYYY-MM-DD.json`，记录当日快照中的 ID 集合、事件数组、来源健康状态和生成时间。新增事件保留完整的模型/资源字段；缺失字段在页面显示“未提供”，不做推测。

## 页面

静态生成 `/logs/index.html`，按日期倒序展示。每一天显示新增、恢复、下线和来源状态计数。新增卡片展示提供商、类型、免费机制、额度、有效期、地区、注册要求、技术参数、官方链接、证据和核验状态；下线区域展示最后出现时间、下线依据和替代入口。

## 自动化与安全边界

每日 workflow 在北京时间早上运行，先完成成功的模型目录扫描，再生成日志并重建静态页面。只提交日志、模型目录快照、日志页面和 sitemap 相关产物。扫描失败不会产生下线事件；候选发现仍标记为“待核验”，不提升为已验证资源。
