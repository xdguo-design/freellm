# 首页主视觉与菜单导航设计

## 问题拆解

- **目标：**缩短首页首屏主视觉占用高度；站内主菜单切换时保持左侧导航稳定，只替换右侧页面内容。
- **范围：**调整首页 `.prototype-hero` 的桌面与手机布局，并修复菜单切换时重新加载全部样式表造成的整页闪动。继续沿用现有 SPA 路由，不重建导航框架。
- **约束：**静态多页站点；保持现有 DOM、路由、插画、标题、描述和按钮，不引入依赖或新导航框架。工作区有其他未提交改动，应只改本任务需要的文件。
- **假设：**用户确认了仅压缩首页主视觉；桌面目标高度约 240px。手机现有至少 430px 的首屏高度需要压缩，同时保留所有文案和按钮可读、可操作。

## 方案对比与选型

1. **沿用现有 SPA，复用相同样式表（选用）：**改动集中在共享导航脚本和首页关键 CSS；导航继续通过 History API 更新 URL 并替换页面内容，左侧共享菜单及相同 CSS 节点保持挂载，避免整页闪动。
2. **将页面装入 iframe 或重建应用壳：**理论上能隔离右侧内容，但会增加跨页样式、搜索、焦点、历史记录和响应式适配成本；当前站点已有共享壳和 SPA，不采用。

## 交互与样式规格

- 菜单点击后 URL、页面标题、主内容和当前菜单项同步更新；常规同源主菜单导航不触发整文档加载。
- 左侧菜单节点保持不变；右侧路由内容替换，滚动回到顶部；浏览器前进/后退恢复对应路由。
- 桌面首页主视觉目标高度约 240px；插画应随容器一同收紧，不能溢出并遮挡统计卡片。
- 手机首页主视觉应比当前 430px 最小高度更紧凑；保留标题、描述、操作按钮及必要插画，并确保内容不会互相覆盖。
- 其他页面的标题区、菜单外观、首页以下内容和路由语义不在本次样式修改范围。

## 失败模式与防护

- **目标页缺少共享菜单结构：**不得静默显示半更新页面；保留现有导航错误处理与标准整页回退。
- **样式表加载失败或很慢：**等待新样式最多 2.5 秒；保留当前页面样式，之后仍可完成切换。
- **快速连续点击导致旧请求覆盖新路由：**沿用请求中止机制；验证最终 URL 与内容对应最后一次点击。
- **hero 缩短后插画覆盖下方内容：**同步检查插画尺寸与定位，使用桌面和手机视口确认统计卡片不被遮挡。
- **手机内容被裁切：**以内容自适应高度为主，不通过固定高度隐藏文案或按钮。

## 验收与验证

- 浏览器手动点击首页主菜单到模型页，确认左侧菜单和相同样式节点保持、右侧内容更新；检查控制台是否出现导航回退警告。
- 连续快速切换菜单，并使用浏览器后退/前进，确认路由、标题和激活菜单项一致。
- 在桌面视口检查首页主视觉约 240px，插画不越界遮挡统计卡片。
- 在手机视口检查首屏高度确实缩短，标题、说明、按钮和插画仍清晰可用。
- 仅对本次改动相关行为做手动验证，不新增自动化测试套件。
