# FreeLLM 内容缺口补齐与增长路线图

更新时间：2026-10-07
适用项目：FreeLLM（freellm.top）
文档性质：内容策略与编辑执行规划；不是产品功能实施授权

## 1. 文档说明

### 编制目的

把全站内容审视中发现的缺口转成一份可分阶段执行、可复核的路线图，帮助 FreeLLM 从“能发现资源”进一步做到“能判断、能开始使用、能在额度或环境变化后继续使用”。本路线图以现有站点和仓库为基础，优先补齐实测证据、上手教程和免费额度对比，再扩展 Agent、大陆可用性、Workflow、本地运行及信任治理内容。

### 站点现状摘要

FreeLLM 已形成面向中文用户的免费 AI 资源目录，覆盖模型、提供商、Skills、工具、Workflow、更新、社区、关于和提交资源等页面。现有优势包括资源核验机制、地区标注、优先引用官方来源、部分模型和 Skill 的实测记录，以及静态页面和结构化数据基础。

### 核心问题

目录覆盖已具备规模，但不少页面仍停留在“列出资源和条件”；用户真正需要的实测证据、首次调用路径、限制解释与后续迁移方案还不完整。

### 范围与边界

- 覆盖内容规划、编辑标准、信息架构和分阶段交付建议。
- 保持“免费资源目录、证据驱动、官方来源优先”的站点定位。
- 不把未经验证的额度、可用性、模型能力或合规结论写成确定事实。
- 本文中的阈值是建议的首轮运营目标；发布前应结合现有基线复核。
- 规划不等于对生产站点进行修改、发布或对外承诺。

## 2. 内容缺口全景

### 已有但薄弱

| 模块 | 当前基础 | 主要缺口 |
|---|---|---|
| 精选模型与模型对比 | 有模型卡片、上下文和输出等字段，也有对比入口 | 速度、中文样本、多模态验证、限流表现和地区实测覆盖不足；对比数据可能不齐 |
| Skills 与 Workflow | 有 Skill 目录和部分 e2e、task、artifact、blocked 测试记录；已有 6 个常用配方 | 缺少可复制命令、最小输入输出、依赖说明、失败案例和换模型后的调整方法 |
| 浏览器工具 | 有 Base64、哈希、JWT 等本地工具集合 | 和免费模型/API/Agent 的使用场景衔接弱，用户不易理解它与主站定位的关系 |
| 社区与反馈 | 有社区页和资源提交入口 | 纠错处理结果、贡献者致谢、审核进度和反馈沉淀较少；提交渠道以邮件为主 |

### 明显缺失的方向

1. **首次调用教程与场景指南**：注册、密钥、第一次请求、常见错误、额度耗尽后的迁移路径。
2. **免费额度真实可用量**：把官方 RPM/TPM/日限额与典型任务估算、观测限制放在一起。
3. **大陆可用性说明**：注册要求、手机号/实名要求、访问路径、实测时间和环境边界。
4. **Agent 专项比较**：长期记忆、本地文件、浏览器操作、权限边界、免费条件、邀请与地区状态。
5. **本地运行路径**：推理工具、量化模型、最低硬件和云端免费 API 的适用差异。
6. **隐私与安全**：对话数据保留、敏感信息处理、自建网关的密钥和日志风险。
7. **英文版入门路径**：英文用户从发现资源到成功调用的完整路径。
8. **变更通知**：除 Atom feed 外，提供商或资源变更的关注体验及限时活动到期信息。
9. **贡献与治理透明度**：数据字段、核验流程、纠错状态和社区贡献说明。

## 3. 优先级框架与成功标准

优先级按用户能否开始使用、信息是否容易过期、现有证据基础和实施成本综合判断。先做能直接回答“怎么开始”和“免费条件是什么”的内容，再扩展相邻主题。

| 级别 | 定义 | 建议验收方式 |
|---|---|---|
| P0 | 直接降低首次使用门槛或补齐核心决策信息 | 页面可独立完成任务；核心声明有官方来源或明确实测记录；关键字段完整率达到 90% |
| P1 | 补齐站点已推广主题的判断方法与使用深度 | 对比维度可横向比较；限制、地区和验证日期清楚；每项结论能追溯到来源 |
| P2 | 增加替代路径、隐私信任或回访能力 | 有清晰适用场景、风险边界和维护责任人；不制造无法持续维护的承诺 |
| P3 | 扩大国际覆盖和社区治理能力 | 能持续维护，且有明确的数据来源、更新节奏与运营负责人 |

### 首轮量化目标（建议值）

- P0 首批 8 篇提供商教程发布前，教程必填字段完整率 100%；至少 6 篇完成实际调用复核，剩余条目标注未实测及阻塞原因。
- 首批额度对比至少覆盖 5 个常见模型、每个模型至少 2 个接入平台；所有额度数字标出官方来源、核验日期和适用条件。
- 精选模型实测首批覆盖 10 个模型；每个模型记录至少 3 次速度样本和一份固定中文任务样本，无法公平比较的项目标记为不可比。
- 新增内容上线后 30 天，记录自然搜索点击、教程到提供商页面的点击、复制命令交互（若已有可用且合规的统计）及纠错数量；不为采集这些指标增加未经批准的用户级跟踪。
- 过期或无法复核的额度信息在发现后 2 个工作日内标记待复核或下线；每月至少完成一次 P0 内容巡检。

以上目标用于首轮复盘，不代表当前已有数据基线。上线前记录基线，复盘时同时报告分母、采样时间和无法归因的部分。

## 4. P0 详细规划

### P0-A：精选模型实测

建立小规模、可重复的测试集，不追求对所有模型排名。首轮优先选站点已有精选模型、国内用户常见模型以及同模型可跨平台接入的组合。

每个模型记录：

- 模型标识、提供商、接入端点、模型版本或快照（可获得时）。
- 测试日期、地区、客户端/SDK、网络类型、是否流式输出、采样参数。
- 首 token 延迟、完整响应耗时、生成速度 tokens/s；样本数和统计方式（中位数、范围）。
- 固定中文任务输入、输出样本、人工评价维度和评分说明。
- 图片、音频、视频等能力的输入样例和观察结果；只记录实际验证过的模态。
- 限流/错误码、重试后行为和已知的环境差异。
- 官方文档链接、实测操作者或复核方式、下次复核日期。

**比较约束：**相同提示词、输出长度目标、客户端参数和测试环境优先；不同上下文、模型版本、平台封装或排队条件必须披露。速度数据不跨不等条件直接排名，中文质量样本展示原始输入和输出，不把单次主观结果表述为普遍能力结论。

### P0-B：从零到第一次成功调用教程

首轮按 8 家提供商规划教程。候选应从当前目录中已有、用户常见且官方文档可查的服务选择；可先评估 Google AI Studio、OpenRouter、SiliconFlow、Groq、Cerebras、ModelScope、NVIDIA NIM、阿里云百炼。最终名单在逐家核对注册、地区、免费条件与官方 API 文档后确定，不能仅因名称出现在候选表就暗示当前可用或有免费额度。

每篇教程统一包含：

1. 适用对象和完成后能做什么。
2. 注册与密钥获取步骤，注明手机号、实名、地区、信用卡等要求的核验状态。
3. 选用的模型、免费额度条件、重置周期和来源链接。
4. 最小 `curl` 请求，以及 Python 示例；密钥通过环境变量传入，不写入源码或截图。
5. 成功响应的结构示例和如何判断请求真正成功。
6. 常见错误码、限流、地区访问失败、模型名错误和排查步骤。
7. 额度耗尽或不可用时的替代提供商和迁移注意事项。
8. 测试环境、最近核验日期、适用范围和反馈入口。

教程必须在不暴露密钥的干净环境中走通一次；未能走通的内容可以发布为“待验证/注册受限”说明，但不能写成完整成功教程。

### P0-C：同模型跨平台额度与限制对比

从至少 5 个模型开始，比较官方 API 和目录中常见的兼容平台。每个模型一行或一个可筛选组，字段至少包括平台、模型 ID、免费额度类型、RPM、TPM、日/月限制、上下文限制、注册条件、地区说明、是否需绑卡、来源、核验日期、实际调用状态。

“可用量估算”单独列出方法：使用固定典型任务（例如输入约 1,000 tokens、输出约 500 tokens），按公开 token 或请求上限推算理论请求数；若平台不公开必要参数则显示“无法估算”。实测请求数、官方上限和推算值分栏展示，不能混为同一个额度数字。多密钥轮询只描述服务条款允许范围内的官方行为，不指导规避限流或创建虚假账户。

## 5. P1 详细规划

### Agent 专项页

提供统一对比维度：产品形态、长短期记忆、本地文件访问、浏览器操作、代码执行、权限确认、数据处理说明、免费条件、邀请/候补状态、支持地区、验证日期和官方来源。把“产品宣称”“目录核验”“实测结果”分开显示。增加“大陆可用”筛选前，定义注册可达、主要功能可达、长期稳定三种状态，避免一个标签覆盖多种情况。

### 大陆可用性系统说明

按访问阶段记录：官网可访问、账号可注册、手机号/实名要求、控制台可访问、API 可调用、可用模型范围。标注测试日期、网络环境和结果置信范围。代理或加速相关内容只陈述服务方条款和访问事实，不提供规避制裁、伪造身份或绕过服务限制的操作建议。官方条款不明确时写明“未找到明确说明”，不代替法律意见。

### Workflow 配方加深

为现有 6 个配方补充先决条件、逐步操作、最小输入输出、失败排查、可替换模型、上下文/成本/质量变化、人工复核点。每个配方应说明哪些步骤依赖特定服务，哪些可以迁移到其他模型或本地工具。

## 6. P2 / P3 内容方向

| 优先级 | 方向 | 首个可交付内容 | 维护注意事项 |
|---|---|---|---|
| P2 | 开放权重与本地运行 | Ollama、LM Studio、llama.cpp 的入门路径；按显存/内存区间给模型量化选择 | 版本和显存需求经常变化，引用官方安装和模型卡；区分最低可启动与可用体验 |
| P2 | 隐私与数据保留 | 服务商数据保留字段说明、敏感场景选择清单、自建网关安全检查表 | 只转述官方政策；标明政策日期，不为第三方作隐私保证 |
| P2 | 变更通知 | 提供商更新订阅、限时优惠到期列表的轻量方案评估 | 先复用 Atom feed 和现有数据；确认维护成本后再增加邮件或公众号渠道 |
| P3 | 英文版 | 英文“Getting started”主路径和一组英文常见问题 | 先翻译并适配已核验内容；中文页面更新后同步复核英文内容 |
| P3 | 社区治理 | 公开数据 schema、核验方法、贡献者致谢和处理量摘要 | 不公开个人邮箱或未处理投稿内容；审核队列状态需避免泄露投稿者信息 |

## 7. 数据与内容标准

### 模型实测字段

建议结构：`modelId`、`providerId`、`endpoint`、`modelVersion`、`testedAt`、`region`、`environment`、`promptId`、`sampleCount`、`ttftMs`、`latencyMs`、`outputTokens`、`tokensPerSecond`、`modalityChecks`、`rateLimitObservations`、`sampleOutput`、`methodology`、`sources`、`reviewedAt`。缺失值使用明确的 `unknown` / `not-tested` 状态，不用猜测值填充。

### 额度对比字段

`providerId`、`modelId`、`quotaType`、`quotaValue`、`quotaPeriod`、`rpm`、`tpm`、`contextLimit`、`registrationRequirements`、`regionStatus`、`billingRequirement`、`officialSourceUrl`、`checkedAt`、`observedStatus`、`estimationMethod`、`notes`。官方额度、人工实测和理论估算必须使用不同字段或标签。

### 来源与更新标准

- 额度、条款、地区和注册要求优先引用官方定价、文档、政策或控制台说明。
- 每条易变信息记录抓取/人工核验时间；页面顶部展示最近复核日期。
- 过期信息不静默沿用：先标记待复核，再按核实结果更新、降级或移除。
- 第三方帖子和社区报告可作为发现线索，不能单独支撑高影响事实。
- 实测结论包含环境与方法，允许重复测试和纠错。

### 合规红线

- 不公开或提交真实 API Key、账号凭证、个人身份信息和用户对话。
- 不建议绕过地区限制、伪造身份、滥用多账号或规避服务商限流。
- 不将免费额度宣传为永久、稳定或无条件可用。
- 不把单次调用结果推广成普遍性能或质量结论。
- 不声称服务商“不会留存数据”，除非官方政策明确且仍在有效期内；同时说明政策范围。

## 8. 信息架构建议

| 页面/路径建议 | 内容 | 优先级 | 关联现有入口 |
|---|---|---:|---|
| `/guides/first-api-call/` | 首次调用总览与提供商选择 | P0 | 指南、模型页、提供商页 |
| `/guides/providers/<provider>/quickstart/` | 单提供商注册与调用教程 | P0 | 对应提供商与资源详情页 |
| `/models/compare/` 或现有对比入口增强 | 同模型跨平台额度、限制和实测对比 | P0 | 模型精选页、加入对比 |
| `/models/evaluations/` | 实测方法、样本和结果 | P0 | 精选模型卡片 |
| `/agents/compare/` | Agent 能力与可用性对比 | P1 | 首页 Agent 卡片、工具页 |
| `/guides/mainland-access/` | 注册、访问、调用的分阶段说明 | P1 | 地区筛选、提供商详情 |
| 现有 Workflow 详情页增强 | 失败排查、替代模型和质量控制 | P1 | Workflow 页、Skills 页 |
| `/guides/local-models/`、`/privacy/` | 本地运行、隐私与安全内容 | P2 | 开放权重、About、工具页 |

新增路径优先复用现有生成器、路由和页面模板；具体实现前先做仓库级设计，避免形成彼此重复的静态页面。

### 现有页面增强点

- 模型卡片：显示实测状态和日期；未测数据使用可见的“未实测”，不留空造成误读。
- 对比入口：无可比数据时解释缺失原因，并引导用户看已有条件字段。
- Skills/Workflow：为每个可复用条目增加复制命令、输入输出和失败恢复。
- 工具页：用少量真实场景串联免费模型输出与本地工具，例如 JSON 清洗、文本编码和请求调试。
- 提交页/About：展示核验方法、纠错入口和数据更新政策。

## 9. 实施路线图（建议 8–10 周）

| 阶段 | 周期 | 交付 | 退出条件 |
|---|---:|---|---|
| 准备 | 第 1 周 | 选定模型、教程提供商和额度对比样本；建立来源与测试模板；记录流量和内容基线 | 候选清单、核验字段和责任人明确；不确定项被标注 |
| P0 | 第 2–4 周 | 首批 8 篇教程；至少 5 个模型的跨平台额度对比；10 个精选模型实测批次 | 教程按统一模板完成；额度来源和日期齐全；实测方法可复跑 |
| P1 | 第 5–7 周 | Agent 对比页、大陆可用性说明、6 个 Workflow 配方补深 | 对比状态定义统一；地区声明含环境和日期；配方含失败路径 |
| P2 / 复盘 | 第 8–10 周 | 本地运行与隐私指南初版；评估变更订阅；复盘 P0/P1 数据决定 P3 顺序 | 输出指标、纠错记录、维护成本和下一周期建议 |

### 人力与周节奏建议

- 内容负责人：维护范围、优先级和发布审核。
- 核验编辑：复核官方来源、注册路径和页面声明。
- 实测执行者：按固定模板运行调用与模型任务，保存去敏后的结果。
- 工程协作：评估页面路由、数据 schema、生成器、导航和搜索曝光；先出单独设计再改代码。
- 每周节奏：周初锁定本周条目；周中完成核验与初稿；周末复核易变字段和发布记录。小团队可由同一人承担多个角色，但每篇 P0 内容发布前应有第二人复核关键事实。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 免费额度或条款变更 | 页面迅速过时，用户调用失败 | 记录官方来源和核验日；限时条件加到期字段；过期先降级提示 |
| 地区、网络和账号环境差异 | 实测结论无法普遍复现 | 明确记录测试环境；区分注册、控制台和 API 调用阶段 |
| 实测资源不足 | 覆盖量不足或样本失真 | 先选小规模代表性样本；公开样本数和限制，不用未测数据补齐表格 |
| 主观评价偏差 | 质量排名误导读者 | 发布原始样本、评分维度和方法；将主观判断与客观指标分开 |
| 合规或 ToS 风险 | 用户按教程操作后违反服务条件 | 引用官方条款；不提供规避限制的操作；遇到不明确内容标注不确定 |
| 目录与指南重复维护 | 多处信息不一致 | 指南链接回权威资源条目；额度和提供商事实尽量由单一数据源维护 |
| 页面数量膨胀、搜索噪声 | 内容薄页稀释站点质量 | 以实用完整度作为发布门槛；不为每个关键词机械生成页面 |
| 维护能力不足 | P2/P3 长期无人更新 | 明确责任人和更新时间；维护成本高的订阅渠道先做评估，不先承诺 |

## 11. 指标与复盘

### 过程指标

- 每篇 P0 内容的官方来源覆盖率、核验日期完整率、实测完成率。
- 教程首试成功率及失败原因分类（地区、注册、密钥、模型 ID、限流、网络）。
- 额度记录的待复核数量、平均复核周期和过期未处理数量。
- 实测任务的样本数、环境记录完整度和复跑一致性。

### 结果指标

- 首次调用教程的自然搜索点击与站内入口点击。
- 教程到对应提供商/模型详情的点击率。
- 对比页的使用率、筛选行为和进入详情页的比例（只使用站点现有且合规的统计能力）。
- 用户纠错量、纠错解决时间、重复出现的失败原因。
- 复盘 P0 发布前后 30 天的变化；注明季节性、搜索收录延迟和其他活动造成的归因限制。

### 复盘节点

1. **准备阶段结束：**样本是否足够代表核心用户问题，来源能否支持发布。
2. **P0 上线后第 2 周：**教程卡点、调用成功率和错误内容；优先修正错误事实。
3. **第 8–10 周：**按使用数据和维护成本决定扩充、合并或暂停某些内容方向，并确认下一周期责任人。

## 12. 附录

### 首批提供商候选

以下是从现有站点覆盖方向整理出的核验候选，不是免费额度或大陆可用性结论。最终首批名单需按官方文档可查性、目标用户需求、同模型可比性和实际注册/调用条件排序。

| Google AI Studio | API Key、模型列表、配额说明、地区和账单条件 |

### 对比模型候选方向

优先挑选至少两个平台都能按相同或明确可映射模型标识访问的模型；覆盖通用对话、代码、中文推理和多模态中的两至三个方向。最终选择基于当日官方目录与实际可调用状态，不在此处预设固定模型名或免费状态。

### 工程衔接

内容先以可复核的编辑数据和来源登记为准。若需新增 schema、比较组件、教程模板或测试数据，应另行完成仓库设计与影响评估后实施。保持现有静态站点架构，避免将动态服务、用户账户或个性化跟踪作为本路线图的默认前提。

### 文档维护

每次路线图复盘更新“更新时间”、候选清单、阶段退出条件和风险状态。提供商官方政策变更只更新对应事实数据和教程，不为保持文档完整而复制多份易变额度数字。
