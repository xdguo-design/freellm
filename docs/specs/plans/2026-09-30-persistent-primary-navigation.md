# FreeLLM 持久化主导航实施计划

> **给代理执行者：** 在本会话按勾选推进。每个页面脚本需要确认其启动方式和页面卸载时的清理责任。保留工作区已有未提交改动。

**目标：** 让七个一级主菜单共享同一个运行时侧栏，切换页面时只更新页面主体，不触发完整文档导航。

**架构要点：** 新增站点导航控制器，通过 Fetch、History API 和 DOMParser 在静态 HTML 页面间导航；侧栏和顶栏 DOM 保持不变。页面内容替换后同步元数据、样式和页面状态，并按页面生命周期清理和挂载交互；原生静态页面继续承担直接访问和失败回退。

**技术栈：** 原生 JavaScript、静态 HTML/CSS；仓库没有统一 JS 测试命令。本计划遵循当前会话“未要求时不添加或运行测试”的约束，以代码审查和用户可见行为为交付依据。

**关联设计文档：** `docs/specs/2026-09-30-persistent-primary-navigation-design.md`

---

## 文件与职责

- 新建 `js/site-navigation.js`：拦截主菜单导航、获取目标文档、保留站点壳、更新历史和维护页面生命周期。
- 修改七个一级页面 HTML：在 `body` 开始处同步加载导航控制器，使它在可见菜单之前接管导航。
- 修改 `js/freellm-sync.js`：在所有现有页面共享模块中加载导航控制器，并将运行时补建的主菜单统一为七个一级入口。
- 修改 `js/reference-shell.js`：将共享页面壳挂载变为可重入行为，并避免每次切页重复添加全局快捷键监听器。
- 修改 `js/homepage.7eeed4fbb5.js`：在离开首页时清理首页抽屉的全局键盘监听器。
- 修改 `scripts/build_static.py` 与 `scripts/build_seo_pages.py`：让后续构建页面也在主体内容前加载导航控制器；两个构建器已有七个平级入口。

## 完成条件

- 七项菜单在运行时共享同一 `.fl-site-rail` DOM；普通菜单切换不触发完整文档加载。
- 主体、标题、URL、当前菜单和前进/后退保持一致；各页面交互在进入后启动，离开后清理。
- 页面直接访问和刷新仍由对应静态 HTML 提供内容；请求失败时回退到浏览器原生导航。
- 七项导航始终各自独立处于一级，不出现额外分组或第八个主菜单项。
