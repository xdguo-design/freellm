# FreeLLM 发帖文档与辅助发布实施计划

> **给代理执行者：** 推荐配合 `subagent-driven-development（子代理驱动开发）`（每任务独立子代理 + 两阶段审查）或在本会话内按勾选逐步执行并在批次节点与用户确认。任务使用 `- [ ]` 勾选跟踪。

**目标：** 生成一份可直接复制到产品发布站、开发者社区和创业目录的 FreeLLM 发帖文档，并用浏览器辅助完成公开提交表单，在登录、验证码和最终发布前保留人工接管。

**架构要点：** 内容与发布动作分离。Markdown 文档保存每个平台的提交地址、审核限制、字段文案和当前状态；浏览器辅助只读取该文档并逐站填写，不保存密码、不绕过验证码、不自动点击最终发布。

**技术栈：** Markdown、PowerShell 只读检查、Codex 浏览器辅助；验证命令为 `git diff --check` 和 `pytest -q`。

**关联设计文档：** 本任务的设计已在当前对话中获得用户批准，核心范围为“发帖文档 + 浏览器辅助提交”。

---

### 任务 1：创建发帖文档

**涉及文件：**
- 新建：`docs/marketing/freellm-submission-posts.md`
- 参考：`README.md`、`design/free-china-ai-index.html`、`data/offers.json`

- [ ] **步骤 1：整理产品事实和提交站清单**

使用当前仓库确认产品名称、官网、GitHub 地址、产品能力、已收录条目数量和截图文件名。把 Product Hunt、V2EX、SaaSHub、Peerlist、Uneed、MicroLaunch、Launching Next、BetaList、Hacker News、GitHub Awesome List、HelloGitHub 和 FinancesOnline 写入文档。

- [ ] **步骤 2：写入各平台可复制文案**

每个平台必须包含标题、短描述、长描述、标签、首条评论或投稿正文、提交地址、必填素材和当前状态。文案必须区分中文社区、英文产品目录和技术社区，避免同一段广告文案批量复制。

- [ ] **步骤 3：写入明确的“不投”清单**

将 AlternativeTo、SourceForge、G2、Gartner、StackShare 和当前的 DevHunt 标为暂不提交，并写明原因，避免后续自动化误投。

- [ ] **步骤 4：写入浏览器辅助发布规则**

明确允许自动填写普通产品信息；登录、验证码、上传文件和最终发布动作必须停下等待用户接管或确认；禁止把密码、OTP、API Key 写入文档或脚本。

### 任务 2：文档质量验证

**涉及文件：**
- 检查：`docs/marketing/freellm-submission-posts.md`

- [ ] **步骤 1：执行 Markdown 与链接检查**

运行：`git diff --check`

预期：命令成功退出且无空白错误。

- [ ] **步骤 2：执行现有项目测试**

运行：`pytest -q`

预期：已有测试通过；若失败，记录为既有工作区问题，不修改无关文件。

### 任务 3：浏览器辅助提交

**涉及文件：**
- 更新：`docs/marketing/freellm-submission-posts.md` 的“提交记录”章节

- [ ] **步骤 1：打开第一个目标平台**

从 Product Hunt 或 V2EX 开始，读取文档中的标题、描述和地址，打开对应提交入口。

- [ ] **步骤 2：填写非敏感字段**

只填写产品名称、官网、描述、标签和截图等用户已明确授权的产品资料。遇到账号登录、验证码、文件上传或权限提示时暂停。

- [ ] **步骤 3：人工确认最终发布**

在平台显示最终提交按钮时，将当前页面和待提交内容交给用户确认；未经确认不发送表单、不发布帖子。

- [ ] **步骤 4：记录结果**

提交成功后记录平台、公开 URL、提交时间和审核状态；失败则记录页面提示和下一步，不重复提交造成重复条目。
