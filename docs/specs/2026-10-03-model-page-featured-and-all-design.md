# 模型页精选与全量区分设计

## 目标

让 `/models/` 进入后直接呈现 FreeLLM 人工挑选并标注「加精」的模型；用户可以从明显入口进入当前收录的完整模型目录。

## 当前问题

`/models/` 当前是统计说明页，真正目录另在 `/models/all/`；`/models/center/` 的“精选资源”区展示的是 Offer，不是加精模型，而且全量区只预览 24 条。入口层级与用户对模型页的预期不一致。

## 已确认设计

- `/models/` 以「精选模型」为主页面，模型取自 `data/models-curated.json`，每张卡片显示明确的「◆ 加精」标签。
- 页面提供模型名、服务商、上下文、输出上限、模态和来源等模型信息；不把免费状态或 Offer 文案混进模型标签。
- 页面提供带全量数量的「全部模型」入口，跳到 `/models/all/`。该页保留当前完整 `data/models.json` 目录、筛选与分页。
- 厂家目录和免费 API / Offer 保留为独立入口及独立统计口径。
- `/models/center/` 作为旧入口跳转到 `/models/`，防止旧链接继续进入含义不符的页面。

## 验收标准

1. `/models/` 中精选数来自 curated 模型集合，精选卡片均显示「加精」。
2. 精选列表不由 Offer 资源生成，也不将全部模型误标为加精。
3. 「全部模型」入口及数量指向当前完整模型目录，目录本身继续可搜索、筛选和分页。
4. `/models/center/` 自动到达新的模型精选页。
5. 桌面和窄屏下模型卡片均有清晰的区分层级，不出现说明文字压过实际模型列表的首屏。

## 范围与限制

只调整模型目录页面生成逻辑、模型页入口和相应生成测试；不修改 Offer 数据、模型精选名单本身、主页资源精选或厂家目录内容。
