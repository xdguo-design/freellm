# Skills 目录页布局设计

## 目标

把 FreeLLM 的 Skills 页调整为用户提供的 SkillHub 目录参考：顶部有「推荐 / SkillHub / 套件」入口，目录提供横向分类筛选和紧凑技能卡片。继续使用现有技能、合集、搜索、排序、筛选和详情数据，不接入新服务。

## 页面结构与交互

- 「推荐」展示现有热门技能推荐区。
- 「SkillHub」展示完整技能目录；分类 chips、搜索、状态筛选和排序继续作用于同一目录。
- 「套件」展示 `data/skill-recipes.json` 中真实的工作流配方，卡片标明输入、产出并链接到现有 `/workflow/` 配方页（`/skills/lab/` 当前只是旧地址重定向）。
- 三个入口作为页内导航切换内容面板，不触发整页刷新；默认进入推荐视图，浏览器前进/后退保留所选视图。
- 卡片采用参考图的紧凑布局：名称、短描述、分类、来源状态和已有的 GitHub Star / 社区评价数；右上角的加号样式按钮调用现有详情弹窗，展示来源、原文和安装命令。
- 技能数据没有图标字段时，卡片使用分类色和首字母标记，不请求第三方图像。
- 桌面每行 4 张卡片，中等宽度 2 张，窄屏 1 张。分类栏可横向滚动。

## 数据与可信度

- 继续由 `data/skills.json`、技能来源、评价和测试记录生成卡片。
- 只展示已有的 Star 和评价数，不新增虚构的下载量、活跃用户、满意度或安装结果。
- 保留已核验 / 待核验状态以及当前详情弹窗中的来源和安装核对提示。

## 方案取舍

1. **推荐方案：** 以页内三视图重组现有内容，并把技能卡片压缩为四列。复用已有数据和详情交互，配方视图读取真实配方数据，最接近参考图，也让三个入口实际可用。
2. **保守方案：** 保留当前单页长目录，只调成四列卡片和横向分类栏。改动更少，但无法复现截图的三段导航体验。

采用方案 1。没有图标资源和真实安装/收藏接口，因此使用分类标记并让加号打开详情，不伪造安装、收藏或使用统计。

## 失败场景与处理

- 分类或搜索过滤无结果：显示现有空状态，提供清除筛选入口。
- 技能缺少来源、星数或描述：使用现有缺省提示，不留空链接或填造数据。
- 用户快速连续切换视图：只更新当前面板状态，避免旧选择覆盖新选择。
- 小屏横向分类过多：分类栏允许横向滚动，技能卡片降为单列，按钮保持可触达。

## 验收

- 三个入口都切换到对应现有内容，且不整页导航；浏览器前进/后退能恢复所选视图。
- 分类、搜索、状态、排序和卡片详情在 SkillHub 视图继续工作。
- 桌面、平板、手机分别呈现四列、两列、单列卡片。
- 卡片指标只来自仓库数据；页面没有新增第三方图片请求。
- 检查 JS 语法、生成后的 Skills 页面差异，并在本地浏览器手动操作三种视图与筛选。
