# 精选模型与 Agent 页面产品需求文档

**版本**：v1.0  
**日期**：2026-10-04  
**状态**：供原型设计使用  
**目标页面**：`https://freellm.top/models/`

## 1. 背景与问题

### 1.1 背景

FreeLLM 的模型页需要让用户快速找到值得尝试的模型。页面以 FreeLLM 团队筛选、测试并加精的模型为重点，同时为完整模型目录保留明确入口。用户也希望在这个页面发现 AI Agent，例如 Pi、Hermes、WorkBuddy、ChatGPT、Muse 等。

### 1.2 用户与需求

- **正在寻找模型的用户**：希望按语音、图片、声音等用途筛选模型，并快速查看模型来源和特点。
- **正在寻找 Agent 的用户**：希望浏览不同用途的 Agent，并了解它们适合完成什么任务。
- **已有经验的用户**：需要从精选页进入完整模型目录、厂家目录或免费 API / Offer 页面。

### 1.3 当前问题

- 模型精选、完整模型目录、厂家目录和免费 API / Offer 容易被混为一类。
- 用户无法从精选模型页面直观看出精选依据是团队筛选和测试。
- Agent 与基础模型的能力形态不同，需要在同一页面体系中被发现，同时保持清晰区分。
- 新页面若采用另一套视觉风格，会破坏 FreeLLM 网站的一致性。

## 2. 目标与成功标准

### 2.1 产品目标

将 `/models/` 明确定位为 FreeLLM 的精选模型入口：模型精选优先呈现，Agent 作为同页独立内容区；同时提供进入全部模型目录的清晰路径。页面应延续当前线上模型页的视觉风格与全站导航，不另起一套产品界面。

### 2.2 成功标准

- 用户进入页面后能区分“精选模型”“全部模型”“厂家目录”“免费 API / Offer”和“Agent”。
- 用户能按模型类型找到语音、图片和声音模型。
- 精选模型卡片能明确传达其精选及团队测试属性，并提供查看模型来源的路径。
- 用户能从页面进入完整模型目录；Agent 内容不会被误认为模型条目。
- 原型在桌面和窄屏下都维持清晰的信息层级，并与现有页面风格一致。

### 2.3 建议观测指标

- 精选模型卡片及来源链接的点击率。
- “全部模型”入口点击率。
- Agent 区域的曝光与 Agent 条目点击率。
- 类型筛选后的结果浏览和后续点击情况。

## 3. 页面方案

### 3.1 信息架构

页面使用现有 FreeLLM 全站外壳和导航。页面内容按以下顺序组织：

1. **页面标题区**：栏目眉题、精选模型标题和简短说明，说明模型由 FreeLLM 挑选并实测。
2. **目录级入口**：精选模型、全部模型、按厂家、免费 API / Offer，以及 Agent 的入口。各入口含义清楚，不能将 Offer 数量或免费状态当作模型精选信息。
3. **精选模型区**：模型类型筛选、精选模型卡片和进入全部模型目录的链接。
4. **Agent 精选区**：与模型区分隔，展示 Agent 名称、简短用途说明和对应详情或来源入口。

### 3.2 精选模型内容

- 精选列表仅代表 FreeLLM 人工筛选并测试过的模型。
- 每个精选模型应有明确的“团队实测”或“加精”标记。最终标签文案沿用现有页面用词。
- 模型卡片优先展示：模型名称、服务商、能力简介、模型类型、上下文或输出等已有关键参数、模型来源。
- 免费资格、额度、注册要求等访问条件属于免费资源 / Offer 信息，不作为模型精选标签。需要时由来源或资源详情承接。
- 类型筛选至少包含：**全部模型、语音模型、图片模型、声音模型**。
- 类型边界建议在原型中这样表达：语音模型侧重语音识别、语音合成和语音对话；声音模型侧重更广义的音频生成或处理。具体模型归类以现有数据能力为准，不要求原型虚构条目。
- “查看全部模型”进入现有完整模型目录，并在入口处体现目录规模（数量可使用真实当前值或原型占位说明）。

### 3.3 Agent 内容

- Agent 是与模型并列的能力目录类别，不使用模型卡片字段或“模型类型”标签包装 Agent。
- 原型示例包括：Pi、Hermes、WorkBuddy、ChatGPT、Muse。若具体 Hermes 产品指代存在歧义，原型阶段使用名称占位，不补写未经确认的品牌信息。
- Agent 条目展示名称、一句话用途说明和可用的详情/来源入口；只有确实经过团队测试时才显示“团队实测”。
- Agent 区域可以通过页面内入口快速定位，但不得压过精选模型的首屏主次关系。

### 3.4 视觉与品牌约束

- 以线上 `/models/` 页面及 FreeLLM 全站现有设计为基准，沿用现有导航、页面宽度、留白、字体层级、卡片/分隔线、颜色和链接样式。
- 保持现有编辑式资源目录气质：清晰、克制、信息优先。新增内容融入既有组件语言。
- 不引入新的主色、独立品牌标识或与全站不一致的导航结构。
- 不将页面改造成深色控制台、带强渐变的 SaaS 仪表盘或大面积装饰插画风格。
- 内容较多时优先调整分区和信息密度，不用夸张视觉元素争夺注意力。

## 4. 功能需求与用户故事

### P0 — 精选模型发现

**用户故事**：作为寻找可用 AI 模型的用户，我希望先看到 FreeLLM 精选并测试过的模型，以便减少筛选成本。

**验收标准**：

- [ ] 精选区只展示被标记为精选的模型。
- [ ] 每张精选卡片清晰标明精选/团队测试状态，并至少展示名称、服务商、能力简介和模型类型。
- [ ] 卡片提供可识别的来源入口；来源不可用时明确呈现缺失状态，不伪造链接。
- [ ] 精选区不混入 Offer 资源条目，也不暗示所有模型都经过测试。

### P0 — 模型类型筛选

**用户故事**：作为按任务选模型的用户，我希望按语音、图片和声音类别筛选，以便快速缩小范围。

**验收标准**：

- [ ] 页面提供全部模型、语音模型、图片模型、声音模型筛选项。
- [ ] 当前筛选状态易于辨认，筛选结果与类别匹配。
- [ ] 筛选结果为空时有清楚的空状态和恢复“全部模型”的路径。
- [ ] 在窄屏下筛选项仍可操作，不遮挡模型名称和内容。

### P0 — 全部模型与相关目录导航

**用户故事**：作为需要更完整信息的用户，我希望从精选页进入完整模型目录或相关目录，以便继续搜索、筛选或查看访问方式。

**验收标准**：

- [ ] “全部模型”入口与精选模型区在视觉和文案上有区分。
- [ ] 全部模型入口指向现有完整目录；厂家目录和免费 API / Offer 保持独立入口。
- [ ] 入口名称能说明目的，不以一个模糊的“更多”链接替代。

### P1 — Agent 发现

**用户故事**：作为希望使用 AI 助手完成任务的用户，我希望在模型页体系中看到 Agent 精选，以便发现适合自己的 Agent。

**验收标准**：

- [ ] 页面设有独立的 Agent 精选区域，并明确标记为 Agent。
- [ ] 原型至少呈现 Pi、Hermes、WorkBuddy、ChatGPT、Muse 作为示例条目。
- [ ] 每个条目有简短用途说明；若提供链接，链接目标和名称相符。
- [ ] Agent 与模型分区明显，Agent 不参与模型类型筛选或模型数量统计。
- [ ] Agent 区域不挤压模型精选的核心内容和“全部模型”入口。

### P1 — 响应式与现有站点一致性

**用户故事**：作为通过不同设备访问 FreeLLM 的用户，我希望页面在桌面和窄屏上都保持可读且熟悉，以便连续使用站内目录。

**验收标准**：

- [ ] 桌面和窄屏下均沿用现有全站导航与视觉语言。
- [ ] 窄屏下标题、筛选、模型信息和 Agent 信息不发生遮挡或横向溢出。
- [ ] 模型与 Agent 的层级、标签和操作入口仍可辨识。

## 5. 边界与异常状态

- 某类型暂无精选模型时，显示简洁空状态，并允许切换其他类型。
- 模型缺少可选参数时隐藏该参数或显示“未提供”，不以推测值填充。
- 模型来源暂不可用时保留模型信息，并避免显示失效的外链。
- Agent 尚无详情页时，可在原型中使用非交互占位；不得伪装成现存页面。
- 精选数量、全量数量等动态信息应注明口径，避免将模型记录数、厂家数和 Offer 数混算。

## 6. 非目标（Out of Scope）

- 本需求不重新设计 FreeLLM 全站导航、品牌、色彩或全站页面模板。
- 本需求不替换完整模型目录的搜索、筛选、分页能力。
- 本需求不合并模型记录、厂家目录、免费 API / Offer 三类数据口径。
- 本需求不承诺新增模型或 Agent 数据，也不替未经确认的资源补写测试结论。
- 本需求只定义页面体验和原型交付要求，不规定前端实现、数据结构或技术选型。

## 7. 原型交付要求

- 提供桌面版完整页面，并提供至少一个窄屏适配视图。
- 页面应能展示精选模型、类型筛选、全部模型入口和 Agent 精选区的层级关系。
- 至少覆盖默认精选状态、一个模型类型筛选状态、筛选无结果状态，以及 Agent 区域的呈现状态。
- 使用接近现有页面的真实文案和克制的样例内容；避免仅用抽象方框表达核心内容。
- 原型评审重点：全站风格延续、模型/Agent 区分、首屏精选模型优先级、目录入口清晰度。

## 8. 待确认事项

- “语音模型”与“声音模型”的最终分类边界及现有数据映射。
- Agent 条目的正式简介、来源链接，以及哪些 Agent 可标注团队测试。
- 原型中的模型名称、模型数量和卡片参数应使用线上实时数据还是固定演示数据。
