# 每日更新页原型像素复刻

**日期：** 2026-10-01  
**状态：** 用户要求以参考截图为像素级目标，按此实施

## 视觉验收基准

- 唯一桌面基准为 `docs/png/更新.png`，原始尺寸 898 × 1799 CSS 像素。使用同一 Chromium 环境、DPR 1、浏览器缩放 100%，从页面顶端比较完整截图。
- 不把图片用作整页背景。页面由真实 HTML/CSS 和现有业务数据渲染；原型 `design/updates.html` 与 `/logs/` 页面采用同一结构和设计值。
- 对齐侧栏宽度/插画、顶部工具栏、Hero/插画、五张数据卡、筛选行、重点更新与周趋势双栏、今日变化概览、历史变更表、来源健康/自测/月份历、更新说明/订阅区及页脚的顺序、尺寸、坐标、颜色、字号和间距。
- 桌面目标截图区域偏小字密集，以目标图的实际像素比例为准；窄屏允许将多列折叠为可读单列，并保留表格横向浏览能力。

## 页面内容与数据

- 复用 `data/daily-log/*.json` 和现有 `render_daily_log_page` 事件事实，不照抄图中的示例日期、数量、厂商或模型。
- 五项指标、分类数字、重点更新、周趋势、历史表、健康状态和月份历都由日志、当前模型/资源目录或明确的静态说明生成。来源健康百分比、自测耗时等当前无真实来源的数字不伪造；相同版位显示实际状态或中性可用性文案。
- 保留新增、恢复、下线、来源异常的区别；来源失败不会推断为下线。保留中英文切换、真实来源链接、历史日期定位、Atom feed 与目录入口。
- 没有当天变更时显示真实零值/无变化状态，不用示例数据填充。真实更新行不足时维持表格版面，但只渲染真实事件。

## 侧栏更新红点

- 在全站共享侧栏“更新”标签旁显示红点，仅当 `Asia/Shanghai` 当天的日志含至少一个 `new`、`new_route`、`recovered` 或 `offline` 事件（含 `curatedEvents`）时显示。
- 当天没有日志、日志过期、只有 `source_unavailable` 或没有目录事件时隐藏红点。
- 静态站内导航切换后状态保持一致；红点不替代可访问的导航文字或当前页状态。

## 实现边界

- 页面生成源：`scripts/build_seo_pages.py`；输出：`logs/index.html`。
- 专属布局样式：`css/prototype-pages.css`，仅作用于更新页；共用壳层继续使用现有共享导航实现。
- 原型：`design/updates.html`，以 `docs/png/更新.png` 为视觉基准，不得保留与正式页面两套不同版式。
- 红点状态由页面构建产物提供给 `js/site-navigation.js`；应兼容共享导航初始化、客户端站内跳转和旧页面没有状态数据的情况。
- 保留已有工作区修改，特别是更新页真实数据卡片、官网来源、注册说明、自测结果、统计快照、共享导航以及 rail 尺寸变量相关改动。不得覆盖无关页面变更。
- 不修改扫描算法、事件判定或日志 JSON 格式；不运行测试套件，按用户要求通过同视口页面视觉比对和 DOM/链接核对验收。

## 完成标准

1. 在 898px 桌面宽度下，页面主要边界和对齐点与 `docs/png/更新.png` 一致；整页模块顺序和纵向节奏逐段对应，不能缺失图中主要模块。
2. 原型页和正式 `/logs/` 输出使用相同的版式、插画、卡片和表格布局。
3. 页面所有数字和事件来自可追溯数据，不出现原型里的示例数值或伪造的健康率/自测结果。
4. 日期导航、事件来源链接、语言切换、Atom feed、目录入口可用；旧数据与无变化日有清晰状态。
5. 导航红点符合上海时区当天目录变更规则，在所有页面与客户端跳转保持一致。
6. 窄屏内容可读，不能出现整页横向溢出。
