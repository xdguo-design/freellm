# LongCat-2.0 重复卡片合并设计

## 目标

将 LongCat API 和 LongCat-2.0 开源权重两张重复模型卡合并为一张 `LongCat-2.0` 卡，同时保留两种不同的使用路径和限制。

## 方案

- `data/offers.json` 保留一个 `longcat-2.0` 资源记录。
- 使用 `accessPaths` 保存两个入口：`API 调用` 与 `下载权重`；分别记录免费状态、访问条件、接口/仓库、命令和官方链接。
- 首页只渲染一张卡，在模型信息区逐行展示两个入口。
- 详情页增加“使用入口”区块，明确区分 API 与本地权重；默认使用指南保持 API 路径，权重路径单独展示。
- 统一卡片同时归入 API 和开源权重分类，不再生成两个重复 SEO 详情页。
- 原 `longcat-api` 与 `longcat-download` 的内部路径统一迁移到 `/offers/longcat-2.0/`。

## 验收标准

1. 首页只出现一张 LongCat-2.0 卡。
2. 卡片和详情页都能看到“API 调用”和“下载权重”两行。
3. API 路径仍标注“免费额度未确认”；权重路径仍标注“权重免费，算力不免费”。
4. API 与开源权重分类都能筛选到合并后的卡片。
5. 旧的两个详情页不再由构建器生成，相关内部链接全部指向 `/offers/longcat-2.0/`。
