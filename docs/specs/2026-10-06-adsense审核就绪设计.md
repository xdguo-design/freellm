# AdSense 审核就绪整改设计

**日期：** 2026-10-06

**状态：** 独立文档审阅已通过，等待用户审阅
**目标站点：** <https://freellm.top/>

## 背景与问题定义

AdSense 先前邮件通知申请未获批准，但邮件没有指出具体页面或违规项。因此，本设计不把某个原因宣称为 Google 已确认结论，而是根据当前站点内容和结构，优先消除最明显的审核风险。

本轮只读审查发现：

- 当前站点地图合计列出 178 个 URL：33 个常规页面、70 个资源页、46 个厂商页和 29 个模型页。
- 资源目录提供额度、地区、时效和来源等信息，属于站点的核心实用价值，应保留有用页面。
- 模型详情页由同步目录数据生成。抽查页面包含单条外部目录记录，部分注册条件仍为 `unknown`，需要检查这类页面能否独立帮助访客。
- `offers/longcat-api/` 和 `offers/longcat-download/` 的静态页面只说明旧入口已经合并，并指向 LongCat-2.0 正式页。
- Qoder 的公开说明仍包含已于 2026-09-30 结束的优惠条件。其他限时项目也需要检查是否已过期。
- 关于、隐私政策、条款页面、联系渠道、AdSense 代码和 `ads.txt` 已存在；这轮优先级放在内容价值、过期信息与索引质量。

Google 的 AdSense 页面准备指引要求内容对访客有独特价值、导航清楚且页面可供审核；Google 也说明，网站只有通过审核并显示 Ready 后才能投放广告。

## 目标与边界

### 目标

1. 让每个保留索引的页面都能独立解决访客任务，或提供有来源支持的比较、操作与决策信息。
2. 保留资源目录中有实际价值的记录，同时减少模板化、已失效或仅作跳转说明的页面进入索引。
3. 通过可复核的原创指南、透明的核验方法与准确的更新时间，清楚展示 FreeLLM 的独立编辑工作。
4. 保持静态生成、站点地图、规范链接、重定向和 robots 元数据相互一致。

### 范围边界

- 修改站点源文件、内容数据及其静态生成产物。
- 审查现有关于、隐私和条款页面，并在发现信息与实际行为不一致时作针对性修订。
- 保留 AdSense 发布商代码及 `ads.txt`；不创建或扩展广告位。
- 本设计不包含向 AdSense 重新提交审核、调整账户设置或部署生产站点。是否重新提交由用户后续决定。
- 不承诺审核结果；最终审核由 Google 决定。

## 设计方案

### 1. 建立全站页面处置清单

以 `sitemap.xml` 及其子站点地图为基准，逐页审查页面正文、模板重复度、官方来源、更新时间、导航路径和独立用户价值。处置分为：

- **保留并索引：** 页面包含可执行步骤、实测说明、实质性比较，或独立且完整的资源条件记录。
- **补充后保留：** 页面主题有价值，但缺少影响选择或实际使用的关键信息；补充仅限有证据支持的内容。
- **暂不索引：** 页面主要重复模型目录数据，无法提供独立帮助；从对应 sitemap 移除，并用 `noindex,follow` 保持链接可发现。内容成熟后可重新评估。
- **合并跳转：** 旧页面内容已经并入正式页面时，配置永久重定向并移除旧 URL 的 sitemap 记录。

分类依据是实际可用性和独立信息价值，不以固定字数作为准入线。资源目录首页、有效资源详情和有足够操作信息的厂商页应优先保留。

### 2. 清理过期信息和失效路线

检查 `data/offers.json` 中所有有期限的优惠以及页面中的活动文案。过期项目须复核官方来源后，改为明确的已结束状态、从当前优惠入口撤下，或归档到仍能解释历史情况的位置；不得继续作为现行优惠推荐。不得因日期缺失而推断优惠有效。

对已经合并的 LongCat 旧入口，改为指向正式详情页的永久跳转，并同步清理旧页面产物与站点地图引用。构建过程应能持续产生一致的页面集合。

### 3. 补强原创指南与编辑透明度

优先维护三类站内指南：

1. **免费 AI API 选择指南：** 比较免费额度、地区、注册/计费门槛、期限和续费风险，并注明信息来自哪些官方页面。
2. **可用性核验方法：** 说明测试环境、地区、测试日期、网络连通性与响应延迟的测量边界；明确不能把连通性或 RTT 等同于模型生成速度。
3. **FreeLLM 收录与复核方法：** 解释官方来源优先级、收录规则、复查和过期处理方式，以及用户提交纠错的渠道。

每篇指南包括维护者、首次发布日期、最近实质性复核日期、来源链接、方法或判断依据及适用限制。只使用仓库中可追溯的实测材料与官方来源；没有证据的结论不写成实测事实。文章服务于访客任务，不按数量扩写。

### 4. 技术实现边界

- 按现有静态站点模式，数据事实继续维护在 `data/`，页面由现有生成器生成；直接编辑生成页的做法只用于已确认不受生成器覆盖的手写页面。
- 页面处置结果应由站点生成流程稳定复现：canonical、robots、站点地图、内部链接和重定向一致。
- 继续提供 AdSense 代码、`ads.txt`、公开联系渠道及当前法律页面。若隐私页面对 AdSense Cookie 或广告设置的描述与实际设置不一致，则同步修订。
- 不改动与本设计无关的 Agent、模型排序、视觉主题、工作流或用户功能。

## 页面处理数据流

```text
现有 sitemap 与页面
        ↓
逐页审查：价值、来源、时效、重复、抓取表现
        ↓
保留 / 补充 / 暂不索引 / 永久合并跳转
        ↓
更新权威数据与现有静态生成器
        ↓
生成页面、canonical、robots、redirect 和 sitemap
        ↓
对照公开站点逐项复核并整理审核准备清单
```

## 错误处理与内容治理

- 官方来源不可访问或条件不清楚时，将记录标为待复核，不将旧条件继续包装为确定的当前优惠。
- 只有在目标页面已存在且内容对应时才配置永久重定向；目标不明时保留待处理清单，不创建猜测性跳转。
- 生成器若无法稳定表达某种页面处置，则先扩展现有生成机制并校验产物一致性，再批量生成。
- 站点地图和页面索引标记发生冲突时，以页面的实际 `robots` 指令和规范 URL 为准修正生成源，并检查引用路径。

## 验收标准

1. 每个 sitemap URL 均完成处置，且有记录说明保留、补充、暂不索引或跳转的依据。
2. 保留索引的内容页包含用户可用的独立信息；纯目录数据页不因批量生成而自动获得索引资格。
3. 已结束活动不会再出现在当前优惠推荐中；不能确认的活动条件有明确待复核状态。
4. 已合并旧入口跳转到有效正式页面，旧 URL 不再出现在 sitemap。
5. canonical、robots、内部链接和 sitemap 对页面处置表达一致。
6. 新指南内容有可追溯的官方来源、方法、日期和限制；无无法核实的第一手体验声明。
7. 联系方式、隐私政策和 AdSense/广告 Cookie 说明与站点的实际设置相符。
8. 站点发布与重新提交审核均不包含在本轮执行授权内。

## 验证策略

实施后按处置清单检查公开页面及生成产物：逐条核对主要内容、来源、时效和页面标记；复核重定向目标、HTTP 状态、canonical、robots 与 sitemap；确认首页和核心目录可导航、公开联系与隐私页面可访问、`ads.txt` 和 AdSense 代码仍可读取。构建一致性以现有生成器提供的校验能力为准。此设计阶段不运行项目测试或发布。
