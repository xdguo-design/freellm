# FreeLLM 免费模型 API 测评方案（首轮）

日期：2026-10-03  
状态：测评方案草案，待实际注册信息补全  
范围：免费额度内的 API 文本模型；不包含网页聊天、图像、音频、联网搜索或 Agent 工具调用。

## 1. 目标

用相同题目和可复核的评分规则，比较不同平台当前免费 API 模型的回答质量与调用体验。每项结果绑定平台、实际模型 ID、地区、测试日期和免费额度条件。首轮报告先作内部参考，审阅后再决定是否公开到 FreeLLM。

本轮不把不同平台的同名模型视作完全相同的服务；如同一模型可在多个平台调用，会保留为不同的“平台 + 模型”测评项，用于比较服务端表现。

## 3. 注册后需要提供的非密钥信息

注册完成后，只需告知我每个平台是否已就绪，并从控制台记录或截图核对以下项目：

1. 平台名称、API 区域和 API Base URL（若有）。
2. 实际可调用的模型 ID、免费额度剩余量及到期时间。
3. 是否有“免费额度用完即停”或体验模式，以及当前开关状态。
4. API Key 是否已创建；不要把 key 粘贴到聊天或普通文档。

Key 使用本机 Windows Credential Manager 保存。执行测评时只按凭据名称读取，不回显 key、不写入结果文件或 Git。测试输入和输出不放入密钥库。

## 4. 固定测试集

准备 30 道原创、可复核的固定题目，每类 6 题：

| 类别 | 题目数 | 评估重点 |
|---|---:|---|
| 中文问答与事实准确性 | 6 | 是否回答正确、是否区分事实与不确定信息 |
| 推理与数学 | 6 | 计算、逻辑步骤、结论是否一致 |
| Python 编程 | 6 | 代码是否满足要求、边界处理、可运行性 |
| 指令遵循与格式 | 6 | 约束遵循、摘要/改写、结构化输出可解析性 |
| 上下文提取 | 6 | 从合成材料中定位信息、避免编造材料未提供的内容 |

所有模型使用同一题面、同一系统提示和同一题目顺序。上下文题使用相同的合成文本。除代码任务外，单题输出上限建议 1,000 tokens；代码任务上限 2,000 tokens。支持时设 `temperature=0`；其他采样参数保持默认并记录。关闭联网、工具和检索功能。若平台不能关闭思考模式或无法统一参数，报告标记这一差异。

另选 5 道题各重复一次，用于观察回答波动；首轮每个模型最多 35 次请求。测试集版本固定并记录哈希，修改题目后另起版本，不与旧分数直接拼接。

## 5. 评分方法

### 质量分：0–100

每类按 0–4 分量表评分，再按权重汇总：

| 类别 | 权重 |
|---|---:|
| 中文问答与事实准确性 | 20% |
| 推理与数学 | 20% |
| Python 编程 | 25% |
| 指令遵循与格式 | 20% |
| 上下文提取 | 15% |

评分锚点：0 = 错答、空答或未完成；1 = 有少量相关内容但主要错误；2 = 部分正确；3 = 基本正确，有小缺陷；4 = 完全正确并满足全部要求。代码题另运行固定的本地检查用例，按通过比例计分；格式题按是否符合明确约束判分。客观题先按答案要点评分，开放题人工盲评；不使用同一模型给自己打分。

### 运营数据：与质量分分开展示

- 请求成功率、错误类型、P50/P95 延迟。
- 实际模型 ID、平台返回的版本/指纹（若有）、输入/输出 Token 数。
- 免费资格、剩余额度、有效期、限速、注册和开通步骤。
- 额度耗尽后是否停止；所有正式请求的计费显示应为零。

不将注册门槛或速度混入模型质量分。若样本不足、调用失败或模型被替换，就标注“数据不足/平台受限”，不发布总分排名。

## 6. 免费额度、停止条件与数据安全

每个平台正式测试前，由你确认控制台显示目标型号仍有免费额度，并已设置免费用完即停或等效保护。若账户已绑定付费方式、平台无法确认超额停用、出现付费提示或账单非零，立即停止该平台测试，待确认后再继续。

以下情况暂停单个模型并记录，不重试到付费模型：免费额度不足、429 限流持续、模型 ID 失效、响应结构不兼容、账单非零、平台政策或免费资格不清楚。短暂网络失败最多退避重试 2 次；任何重试也计入请求上限。

只提交原创或公开、非敏感的测试输入，不使用个人资料、业务数据、私有代码或秘密。特别是 Google AI Studio 免费层可能使用提交内容改进产品，因此测试题不得含敏感信息。

## 7. 输出物与执行步骤

注册及额度核对完成后按以下顺序执行：

1. 核对平台、模型 ID、免费状态和额度保护开关。
2. 先对每个平台各跑 1 道无敏感内容的连通性检查题；确认返回模型与零费用后继续。
3. 对所有入选“平台 + 模型”运行固定 30 题及 5 道重复题。
4. 保存逐题原始结果、请求元数据和错误记录；日志中清除凭据与授权头。
5. 生成质量评分表、运营数据表和简短结论，列明限制与测试日期。
6. 你审阅报告后，再决定是否增加平台、复测或公开结果。

预期报告至少包含：模型/平台矩阵、各类得分、总质量分、成功率、P50/P95、免费额度快照、失败说明、测试集版本和可复查的逐题结果。
