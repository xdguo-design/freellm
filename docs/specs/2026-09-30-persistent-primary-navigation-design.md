# FreeLLM 持久化主导航设计

- 日期：2026-09-30
- 状态：待用户审阅

## 目标

页面从主菜单切换时保留同一个侧边栏，不整页刷新，也不丢失站点菜单。七个入口（首页、模型、Skills、工具、工作流、更新、关于）均作为独立的一级菜单项展示。地址栏、浏览器前进/后退和当前菜单高亮应与页面内容一致。

## 范围

- 覆盖侧边栏七个主菜单链接；从其他带站点侧栏的页面点击菜单也使用同一套导航行为。
- 保留各页面的独立 URL、服务端静态 HTML 和直接打开能力。
- 普通页面内容链接、外部链接、表单提交和工具内部交互维持原有行为。
- 运行时只保留一个侧栏和菜单 DOM；静态 HTML 继续带有服务端渲染的侧栏，供首屏显示、搜索引擎和 JavaScript 不可用时使用。

## 方案

在站点级导航脚本中拦截同源主菜单链接，获取目标页面 HTML 后更新页面主体内容，同时保留当前侧栏和顶栏节点。同步目标页面的标题、描述、canonical、页面样式、`body` 页面属性与主菜单当前项。主菜单七项共享同一层级，不加入分组或子菜单。

页面专属脚本通过明确的页面挂载/卸载生命周期初始化和清理；切换时卸载旧页面交互，挂载新页面交互，避免重复监听器。切换成功后更新 History API 状态；前进/后退从对应 URL 恢复页面。用户直接访问 URL 时仍由静态页面正常首屏渲染。获取失败或页面不满足预期结构时回退到浏览器原生导航。

## 页面切换流程

1. 仅拦截未被修饰键打开、目标为当前站点、目标是主菜单入口的普通点击。
2. 请求目标静态页面并解析 HTML；在页面结构有效后才替换主体。
3. 保留侧栏与顶栏实例，更新页面主体、文档元数据、页面样式和 `body` 页面状态。
4. 调用页面卸载/挂载生命周期，更新活动菜单并滚动到顶部。
5. 写入历史记录；浏览器前进/后退时执行相同的内容切换，但不重复写入历史记录。

## 错误处理与兼容

- 请求失败、非成功状态、解析失败或缺少主体内容时，执行目标 URL 的原生跳转，保证页面仍可访问。
- 保留服务端渲染的菜单和主体作为无 JavaScript、刷新及深链接回退路径。
- 不拦截下载、外站、`target`、带 `download`、带修饰键的点击或页面内锚点。
- 页面脚本卸载时清理其事件监听器、计时器和观察器；重复挂载同一路由不得重复初始化。

## 验收标准

- 七个主菜单项始终显示为七个平级入口，点击任一入口时侧栏 DOM 实例不变且文档不触发整页加载。
- 菜单切换后页面内容、页面专属交互、标题、URL 和当前菜单高亮对应目标页面。
- 从任意主菜单页面切到首页后首页内容完整显示；菜单间来回切换及前进/后退可用。
- 直接打开任一目标 URL、刷新页面和 JavaScript 关闭时仍能看到对应静态页面与导航。
- 请求目标失败时浏览器正常导航到目标 URL。

## 验证策略

通过浏览器手动检查各主菜单入口、页面功能、活动状态、地址栏、前进/后退、直接访问及失败回退；检查页面加载事件确认菜单切换未触发完整文档导航。验证范围不扩展到站内普通内容链接。\n
