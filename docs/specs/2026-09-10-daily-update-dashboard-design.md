# 每日更新仪表盘设计

**状态：** 已获用户确认，进入实施

## 目标

将 `/logs/` 从“空事件列表”升级为每日更新仪表盘：有真实变更时突出新增、恢复、下线和来源异常；首次基线或当天无变化时，展示当前目录快照、扫描健康度和明确说明，避免页面只剩四行空状态。

## 视觉方向

参考 FreeLLM 首页与用户提供的参考页面：暖灰/浅蓝背景、深蓝大标题、蓝色主操作色、圆角白色卡片、紧凑的状态徽章和清晰的区块层级。日志页继续使用静态 HTML，不引入新的前端框架或运行时依赖。

## 页面结构

1. 顶部导航：品牌、中文/English、返回首页、模型目录。
2. Hero：`每日更新`、日期、扫描完成/首次基线状态，以及“模型 / 提供商 / 资源”三项当前规模。
3. 四项变更统计：新增、恢复、下线、来源异常；每项显示数量和简短解释。
4. 今日目录快照：模型数、提供商数、资源数、模型源状态、资源源状态。
5. 变更流：按新增、恢复、下线、来源异常分组。新增沿用详情卡片；其他事件使用紧凑表格卡片。
6. 无事件状态：当 `baseline=true` 时说明“首次建立基线，后续扫描才会产生变化”；普通无变化日说明“今日扫描完成，未发现变化”。两者都保留目录入口。
7. 历史日期：按已有日志文件生成日期导航，当前日期高亮；没有历史文件时不显示空的日期控件。

## 数据规则

- `events` 是变更事实，只展示实际存在的事件，不把快照条目伪造成新增。
- `baseline=true` 时，统计卡仍显示 0，但 Hero 与空状态必须明确是首次基线。
- `observed.models`、`observed.offers` 用于当前快照计数；提供商数由模型 `providerId` 去重计算。
- `sourceHealth` 显示为健康/失败状态和 `reason`；来源失败不能被解释为下线。
- 事件详情继续使用现有字段和官方来源链接，避免改变数据文件格式。

## 响应式与验收

- 桌面端采用两列统计/快照布局，内容卡片保持可扫描；移动端全部降为单列。
- 页面首屏在 1200px 宽度下至少展示 Hero、四项统计、目录快照和变更流标题，不出现大面积无意义留白。
- 2026-09-10 基线页必须显示 297 个模型、25 家提供商、37 条资源和“首次基线”说明。
- 带新增事件的测试数据必须继续渲染标题、免费机制、额度、注册条件、官方来源和新增原因。
- 中英文切换、旧日志文件、SEO 输出检查和全量测试保持通过。

## 非目标

- 不修改每日扫描算法、事件判定逻辑或数据文件结构。
- 不伪造当前基线日的新增事件。
- 不把所有历史事件一次性展开到首屏；历史仍按日期切换。
