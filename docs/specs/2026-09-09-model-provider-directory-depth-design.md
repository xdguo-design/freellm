# 模型与厂家双目录、详细操作指南设计

## 目标

FreeLLM 采用“参考目录负责广度，本站负责深度”的定位：模型目录覆盖更多模型和厂家，详情页提供经过核验、可以照着执行的访问步骤。

## 现状与问题

- `data/offers.json` 是 37 条免费入口 Offer，不是完整的模型目录。
- `/models/` 当前按 Offer 卡片和分类输出，不能按厂家或模型访问完整表格。
- 当前 Offer 数据没有统一的评分、上下文、最大输出、模态、发布日期、使用量和逐模型状态字段。
- `crawler/freellm_net_discovery.py` 可以发现第三方目录中的模型，但尚未完整保留参考目录的模型元数据。
- 现有 Offer 已有 `command`、`usageGuide`、`accessPaths` 等能力，但每条入口的步骤粒度和字段完整度不一致。

## 产品结构

### 模型目录 `/models/`

一个简洁、可搜索、可筛选的大表。每一行表示“一个模型在一个厂家或平台上的可用记录”，字段包括：厂家、模型、评分、上下文、最大输出、模态、速率限制、发布日期、使用量、在线状态、来源和最后核验时间。

目录数据分为三种状态：

- `verified`：本站已核对官方来源。
- `directory_discovered`：从 freellm.net 等目录发现，保留来源但尚未完成官方核验。
- `stale`：来源超过新鲜度窗口或已无法确认，需要复核。

### 厂家目录 `/providers/`

厂家首页按厂家展示模型数量、免费模型数量、可用入口数量、官方主页和最近更新时间。厂家详情页 `/providers/{slug}/` 展示该厂家的全部模型、免费条件、限制、入口和操作指南链接。

### 模型聚合页 `/models/{slug}/`

将同一模型在不同厂家、平台和入口上的记录聚合在一起，比较各平台的上下文、额度、速率和访问条件。模型页不重复编写平台操作步骤，直接链接到对应的入口指南。

### 入口操作页 `/offers/{id}/`

Offer 负责“如何获得和使用”，每条 access path 独立维护：前置条件、步骤、复制命令、成功验证、额度查看、常见错误、限制和官方来源。模型目录只负责发现，Offer 详情负责执行。

## 数据边界

- `data/models.json`：模型-平台行数据，包含目录字段、来源、状态和更新时间。
- `data/provider-catalog.json`：展示用厂家实体、别名、官方主页、地区和目录关系；不替换现有用于爬虫白名单的 `data/providers.json`。
- `data/offers.json`：免费额度、试用、低价、IDE、网页工具和开源权重等访问入口。
- `data/operations/`：按 Offer 或 access path 保存详细操作步骤；已能复用的内容再回填 `offers.json` 的结构化字段。
- `data/third-party-discovery-sources.json`：继续作为第三方发现源注册表，不把发现结果直接当成官方事实。

评分必须带 `scoreSource` 和 `scoreCapturedAt`；页面显示“目录评分”，不能暗示为 FreeLLM 自有评测。

## 新鲜度

- 页面顶部显示模型总数、厂家总数、最近同步时间和最近核验时间。
- 每行显示 `Online`、`Stale`、`Unknown` 或“待核验”。
- 目录发现记录超过 7 天未见更新时标记为 `stale`；官方核验记录保留自己的核验日期。
- 默认排序优先当前在线、已核验、最近更新，再按评分和发布日期排序。
- 旧数据不静默删除，改为标记过期或不可用，并保留最后一次来源。

## 差异化原则

参考目录解决“有哪些”；FreeLLM 解决“现在怎么用”：

1. 每个厂家入口有独立的注册、Key、Endpoint、模型选择和验证步骤。
2. 每个模型-厂家组合保留自己的限制，不能把一个厂家的额度复制给另一个厂家。
3. 每个命令都能复制，代码块标明环境变量、依赖和预期结果。
4. 详情页说明地区、账号、手机号、信用卡、训练数据和超额计费等前置条件。
5. 任何未核验内容都显式显示来源级别和最后更新时间。

## 第一批重点

先覆盖模型和入口最容易被搜索、也最能体现差异化的组合：Ollama Cloud、OpenRouter、Groq、NVIDIA NIM、ModelScope、SiliconFlow、OpenCode Zen、Freebuff、Muse Spark 1.3、LongCat-2.0、Qwen 和 DeepSeek。

第一批操作指南优先做 API、CLI、Web、Desktop、Cloud 和本地权重六种访问方式；每完成一个厂家就同时补齐其模型列表、官方来源和操作验证。

## 验收标准

- `/models/` 能显示完整模型-平台大表，支持搜索、按厂家筛选、按模型聚合和排序。
- `/providers/` 能按厂家浏览，并能进入厂家详情页。
- 模型页能比较同一模型的多个平台，不混淆额度和来源。
- 已发布的每条重点入口都有独立的步骤、命令、验证方式和官方来源。
- 页面明显展示最后同步和最后核验时间，过期记录有状态标记。
- 第三方目录发现数据不会被标成官方已验证。
- 原有 Offer 页面、分类页、首页筛选、SEO sitemap 和全量测试继续通过。
