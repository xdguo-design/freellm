# Skills 实测与自有评价设计

## 目标

把 /skills/ 从“GitHub 索引 + 第三方评价”改成以 FreeLLM 自己的可重复测试为核心。第三方评论只作为旁证。

## 真实性规则

- 未执行核心任务的 Skill 不显示“已实测”。
- 外部账号、API Key、专有 CLI 或登录态缺失时显示“环境阻塞”，写清阻塞点。
- 同类 Skill 尽量复用同一组固定夹具：产品需求、代码 bug、会议记录、简历/JD、发票、脏文件、文章与提交记录。
- 视觉型 Skill 必须保存实际测试产物或其渲染证据；CSS 模拟示意不能冒充真实截图。
- 分数只在 task/artifact/e2e 后给；source-review 不打分。

## 页面信息优先级

1. FreeLLM 实测状态与分数
2. 测试任务、环境和日期
3. 实际产物 / 截图 / 可打开 demo
4. 我们观察到的优点、缺点、边界
5. SKILL.md 原文
6. GitHub/社区评价（参考）

## 测试层级

- e2e：核心路径真正执行并验证结果。
- artifact：实际生成可视产物并检查结构/交互。
- task：按 Skill 指令完成固定任务，输出可核验文本/代码结果。
- preflight：真实执行到依赖/账号边界后被阻塞。
- source-review：只读过原文，不算实测。

## 第一批证据

本轮已完成 PDF 合并/拆分/文本抽取、调试+TDD+完成前验证、文件整理、发票整理、会议洞察、定制简历、changelog、humanizer、内部沟通，以及多个 HTML/SVG 视觉夹具。后续页面不得把 source-review 伪装成已测试。
