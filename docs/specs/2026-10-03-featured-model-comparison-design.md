# 精选模型适用地区、能力与速度对比设计

## 背景

`/models/` 是人工精选模型入口。当前精选数据有 46 条，包含 `accessRegion`、`modality`、上下文长度、输出长度和官方来源等信息。卡片已展示部分字段，但精选模型缺少一眼可比较的地区适用性、能力类型和真实生成速度。

现有 `offers.json` 中的 `networkCheck` / `speedMs` 是 API 或站点连通耗时，不能代表模型生成速度；它们不得被转写成精选模型的生成速度。

## 目标与边界

- 让用户在精选模型页快速判断模型适用地区、支持的任务类型，以及是否有可核实的速度实测。
- 让用户能在精选模型之间按地区和能力筛选，并横向比较少量候选模型。
- 不改变“精选模型”和“全部模型”的数据口径；只增强人工精选页。
- 不将官网免费额度、网络连通时延或未实测值包装成模型性能结论。

## 方案选择

1. **增强精选卡片并提供轻量横向对比（推荐）**：保留卡片浏览，加入地区与能力筛选；可选最多 3 个精选模型打开对比视图。能保留现有页面结构，同时满足快速发现和比较需求。
2. **只增强卡片**：信息更直观，但多模型比较需要用户反复记忆，不够符合“比较”的目标。
3. **改成全量对比表**：字段密度高，但 46 条数据在窄屏上难读，也削弱精选卡片的浏览体验。

采用方案 1。比较交互只作用于精选集合，不延伸到全部模型目录。

## 页面与交互

### 精选卡片

- 保留现有模型名、服务商、精选标识和来源链接。
- 在显眼位置展示适用地区：`中国大陆可调用`、`海外可调用`、`国内外均可调用` 或 `待核实`。地区状态绑定到具体服务商和 API 路径，不只绑定到模型名称。标签说明已验证接入地区，不等价于法律/合规结论；不能只凭 `accessRegion=global` 断言中国大陆可用。
- 用简短图标标签展示能力类型：文本输入/生成、音频输入/识别、语音生成、图片理解、图片生成、视频理解、视频生成。只有证据能确认输入或输出方向时才显示细分能力；方向不明确时显示“支持图片/音频/视频，方向待核实”，不能从 `modality` 自动推断模型可以生成该媒体。
- 展示速度状态：有模型响应实测时显示对应指标和测试地区/日期；没有数据时显示“未实测”。
- 保留上下文、最大输出、官方来源等次级信息，避免新增字段挤掉模型名和核心标签。

### 筛选与比较

- 卡片区提供地区筛选（全部 / 中国大陆 / 海外 / 国内外 / 待核实）和能力筛选（文本、语音/音频、图片、视频）。筛选可组合，结果数同步更新；无匹配结果时提供清除筛选操作。
- 每张卡片提供“加入对比”操作；最多选择 3 个模型。到达上限时提示先移除一项。
- 对比视图使用可横向滚动的表格/面板，逐列展示模型、服务商、地区、能力、速度指标、测试地区与日期、上下文、最大输出和官方来源。窄屏保留指标名称可读性并允许横向滚动。
- 用户移除单个模型或清空比较时，筛选条件保持不变；页面刷新后不要求恢复比较状态。

## 数据设计

精选模型的地区数据附着在服务路径记录上，并新增明确状态及证据，例如 `verifiedRegions`（`domestic` / `international`）、`regionEvidenceUrl` 和 `regionCheckedAt`。`domestic` 表示从中国大陆网络对该 API 路径完成成功的最小真实模型请求；`international` 表示从中国大陆以外网络完成同样验证。两项都验证成功时显示“国内外均可调用”；只验证一项时只显示对应地区，并说明另一地区未核实；没有成功请求证据时显示“待核实”。单有官方文档或网络探测不算真实模型请求成功。

能力数据新增方向明确的 `verifiedCapabilities` 条目，每条包含能力（例如 `image`、`audio`、`speech_generation`、`video_generation`）、方向（`input` / `output`）、证据 URL 和核验日期。旧 `modality` 只可支持“支持某类输入/多模态信息”的宽泛说明，不可据此声称图片/音频/视频生成。找不到方向证据时以“方向待核实”显示。

速度测试作为独立的 `benchmark` 记录，不复用 `networkCheck` 或精选 Offer 的 `speedMs`。文本生成基准采用版本化固定协议：流式请求、固定的中英文任务样例（语言分别记录，不混在同一比较组）、温度 0（服务不支持时记录实际默认值并与默认值组比较）、最大输出 256 tokens；每次先做 1 次预热，再完成 3 次有效测试，展示 TTFT 和可见输出 token/s 的中位数。TTFT 从请求发出计至首个可见生成 token；输出速度从首 token 后计至流结束，按可见输出 token 数除以该区间秒数。非流式接口不报告 TTFT。测试至少记录：协议版本、提示样例 ID/语言、采样参数、输出上限、指标、测试地区、API 服务路径、测试日期、各次原始结果与汇总方式。

只有同协议版本、同语言与同任务组的记录才可在比较视图中并列速度值；条件不同则分组或显示“不具可比性”。速度是标注 API 路径在对应地区和测试时段的端到端观测值，不代表模型权重的理论性能。暂无真实记录时保持“未实测”，不估算、不继承其他服务商的结果。

`modality` 继续作为能力来源；渲染层只负责归一化标签和图标。地区筛选和比较视图使用相同的标准化字段，避免卡片与筛选口径不一致。

## 速度口径

- “生成速度”指用户经标注 API 路径调用模型时测得的端到端响应数据，不代表模型权重的理论性能。
- 文本任务展示 TTFT 与生成 token/s；同一型号若不同提供商托管，应作为不同服务路径分别记录，不能合并成一个型号速度；横向比较只对齐测试协议一致的记录。
- 目前没有精选模型对应的真实生成基准数据。接口可达耗时继续留在网络/入口健康信息里，不出现在模型生成速度字段中。
- 对图像、音频、视频生成能力先显示能力标签；只有建立相应真实任务的测试方法和记录后，才展示该模态的耗时指标。不用 token/s 比较图像或视频生成。

## 无数据与失败处理

- 缺少地区证据时显示“待核实”，且筛选中归入待核实。
- 缺少速度记录时显示“未实测”；测试超时、限流或无权限也不显示为 0 速度，而应保留单独的未完成/阻塞状态和日期。
- 外部来源链接不可用不影响卡片渲染；无来源时明确提示“暂无来源链接”。
- 筛选结果为空时显示清空筛选入口；比较项被筛选隐藏时不自动移除比较选择。

## 验收标准

1. 精选和全部模型集合保持分离；本次筛选与对比只覆盖精选集合。
2. 每张精选卡片都展示服务路径的地区验证状态、可证实方向的能力标签和速度测试状态；缺字段时准确落入“待核实/未实测”。
3. 仅真实、有日期、测试协议和服务路径完整的生成基准会进入速度显示和对比；`networkCheck` / `speedMs` 不会被当作生成速度。
4. 地区和能力筛选可组合、计数正确，清除筛选后恢复完整精选集合。
5. 最多可同时比较 3 个模型；桌面和窄屏均能读到完整指标名称与数值。
6. 中英文标签一致；模型卡片和对比视图在缺值、无结果、测试阻塞状态下仍可使用。

## 验证策略

- 单元验证数据标准化：地区判定、未知值回退、能力映射、基准记录的服务路径和日期校验。
- 页面生成验证：卡片只显示精选集合、筛选维度来自真实字段、对比区包含约定指标。
- 浏览器验证：组合筛选、空结果与恢复、三项比较上限、移除/清空、窄屏横向阅读和中英切换。
- 使用虚构测试 fixture 验证状态渲染；生产数据只有在真实测试记录存在时才展示数值。

## 实施拆分

1. 确定地区证据和速度基准记录的字段校验规则，并盘点可合法调用且有测试凭据的精选模型路径。
2. 增强精选卡片与地区/能力筛选。
3. 添加最多 3 项的横向比较视图；只并列相同协议和任务组的速度结果。
4. 为可用服务路径执行真实测试；未能测试的条目维持“未实测”或显示具体阻塞原因。
5. 运行数据、页面生成和浏览器验收，再根据结果更新精选页。
