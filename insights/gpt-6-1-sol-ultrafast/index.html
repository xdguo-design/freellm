GPT-6.1 Sol 新增 Ultrafast：速度、价格与 Decisions API，开发者怎么选？

OpenAI API 10 月更新：GPT-6.1 Sol Ultrafast 模式、6 倍标准定价、简单成本示例，以及 GPT-6 Luna 驱动的 Decisions API Beta。

核验摘要
  • Ultrafast：使用 model: gpt-6.1-sol 与 service_tier: ultrafast；受组织速率限制与处理区域条件约束。
  • 官方价格：标准档短上下文下，输入 $2、缓存输入 $0.10、缓存写入 $2.50、输出 $10 / 每百万 Token；Ultrafast 为标准价的 6 倍。
  • Decisions API：处于 Beta，官方称可把文本和图像转换成类型化答案，速度最高可达 Responses API 的 10 倍；应以自己的任务评测验证。

OpenAI API 在 10 月 8 日为 GPT-6.1 Sol 的 Responses API 增加 Ultrafast 档，用于降低生成输出 Token 之间的等待时间。另一个更新是 10 月 6 日进入 Beta 的 Decisions API，由 GPT-6 Luna 将文本和图像转换成类型化答案。

先算清楚 Ultrafast 账单

按无缓存的简化假设，一次请求用 100,000 输入 Token 与 20,000 输出 Token，标准档大约是 0.20 美元输入 + 0.20 美元输出，共 0.40 美元；全部用 Ultrafast 则约 2.40 美元。真实账单还会受到上下文长度、缓存、处理档位和工具费用等规则影响。

什么时候值得开？

  • 可以先测：实时交互、需要多次串行工具调用的 Agent、明显受生成延迟影响的用户体验。
  • 先别默认开启：后台批处理、无需立即响应的报告任务，以及可以用较小/较便宜模型完成的分类工作。

对连续工具调用，OpenAI 官方建议考虑 WebSocket 等持续连接方式，减少每次请求的网络开销。评测时应记录首 Token 时间、端到端耗时、任务成功率、超时和每次成功任务成本，不能只比某个单次速度。

怎样调用

在 Responses API 请求里将模型设为 gpt-6.1-sol，并将 service_tier 设置为 ultrafast。正式流量增长前先查组织限额，并做标准档与 Ultrafast 的 A/B 测试；所有调用都强制使用最快档通常不是最经济的架构。

Decisions API 的定位

Decisions API 适合分类、字段抽取和其他可以用固定 Schema 验证的任务，例如给反馈打标签或从图像中提取明确字段。接入前要评估字段遗漏、模糊样本、低置信度与错误输入，并留出人工复核机制。它是 Beta 功能，不应只凭“10 倍更快”的宣传数字作为 SLA 依据。

FreeLLM 的选型建议

把成本、速率限制、地区和模型能力分开比较：付费高速度档适合明确对延迟敏感的环节，免费 API 或开放权重模型可能适合离线任务和低预算原型，但同样需要核验额度与实际可用性。
