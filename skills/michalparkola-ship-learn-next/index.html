四、建议的操作步骤

  1. 理解问题
  2. 拆分步骤和依赖
  3. 逐项执行或复核
  4. 根据证据验收与复盘

这里是面向读者的实施顺序。准确安装命令、运行器配置与参数以原版 SKILL.md 为准。

五、预期交付物和验收

  • 任务计划
  • 会议纪要
  • 评审报告或行动清单

验收时优先检查文件能否打开、结果是否符合需求，以及来源/公式/代码是否可复核，而不是只看文字描述是否完整。

六、注意事项与能力边界

工作流本身不能证明任务完成；简单任务无需强行增加流程。

GitHub 来源链接可访问、任务级模型回答通过、原工具链端到端跑通是不同的结论。遇到缺少依赖、授权、可执行环境时，应如实标注限制。
