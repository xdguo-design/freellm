# 网站风格参考检查清单

目标是提取可迁移的设计决策，不复制页面。

## 观察维度

| 维度 | 记录内容 | 输出形式 |
|---|---|---|
| 信息架构 | 导航分组、首页入口、详情层级、搜索和筛选位置 | 页面树 + 本项目映射 |
| 信息密度 | 卡片/表格、字段数、留白、首屏可见信息 | 密度等级 + 取舍 |
| 视觉角色 | 背景、文字、边框、强调色、状态色 | 语义 token，不抄色值也不抄品牌 |
| 字体角色 | 标题、正文、元信息、代码区的层级 | 字体职责 + 可替代字体 |
| 组件 | 搜索框、标签、表格、侧栏、详情抽屉、空状态 | 状态矩阵 |
| 交互 | 筛选、排序、复制、展开、键盘和移动端行为 | 交互验收清单 |
| 响应式 | 断点、列数变化、导航折叠、横向滚动 | 移动/桌面差异 |
| 可信度表达 | 来源、更新时间、验证状态、警告和审核标识 | 证据 UI 映射 |

## 借鉴写法

| 同行观察 | 本项目改写 |
|---|---|
| 深色终端式状态面板 | 用自己的 Free AI Index 字段表达扫描状态 |
| 高密度索引表 | 使用本项目的 provider、quota、region、checkedAt 字段 |
| Editorial 大标题 | 换成自己的定位文案和 verified/review 状态语言 |
| 文档式左侧导航 | 只保留本项目真实分类和方法论入口 |

## 版权与边界

- 先读取仓库许可证；许可证不明确时只做抽象描述，不复制代码、图片、Logo、字体文件或原文案。
- 颜色、栅格、圆角、动效等通用设计概念可以作为灵感，但组合后的页面必须有自己的品牌、内容、数据和组件实现。
- 不保存用户登录后的页面、私人数据、浏览历史或带权限的截图。
- 视觉原型应使用短文本或占位 provider mark；生产资产必须来自本项目已核验的官方来源。
- 任何“像某站”“复刻某站”“照着做”请求都改写为信息架构和交互模式参考，并在报告中说明差异。

## 原型验收

- [ ] 至少提供三个方向：深色 Console、Console + Editorial、Docs Directory。
- [ ] 每个方向是独立可打开的 HTML/CSS 原型，不只是文字描述或静态草图。
- [ ] 三个方向使用相同的示例数据，便于比较信息架构和密度。
- [ ] 桌面和窄屏均可读；搜索、筛选、详情入口的意图清晰。
- [ ] 展示给用户选择后，才把选定方向迁移到正式页面。
